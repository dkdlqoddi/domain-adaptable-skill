## 범위
- 쓰기: `<모듈>/**`, 루트가 지정한 전용 보고 파일
- 읽기 전용: `docs/`(CONTRACT 관련 절·SPEC P0·TASKS), `fixtures/<관련 파일>`<, `shared/**`>
- 열지 않음: `<다른 모듈>/**` 전부. 상대 모듈의 동작은 CONTRACT의 샘플 값으로 대신한다.

## 실행·검증
- 실행: `<명령>`
- 검증: `<테스트/스모크 명령>` — 슬라이스를 끝내기 전에 반드시 통과시킨다.
- 순서: 픽스처로 먼저 돌아가게 만들고 → 그다음 실제 연동.

## 규칙
- 계약·공유 docs·Git 인덱스를 바꾸지 않는다. 계약 변경이 필요하면 전용 보고에 `BLOCKER:`를 적고 멈춘다. 루트가 TASKS를 갱신한다.
- <역할에 맞는 규칙 한 줄. 예: 외부 도구·장비를 부르는 모듈은 실제 도구 없이 `--dry-run`(픽스처 재생)으로 끝까지 돌아야 한다 / 화면 모듈은 다른 모듈 코드를 열지 않고 fixtures 샘플로 먼저 완성한다>
- 루트 `CLAUDE.md`의 작은 코드 원칙이 그대로 적용된다.
- 끝낼 때 보고: 검증 명령과 출력, 바꾼 파일, 알고리즘·복잡도·경계 사례·근거 함수/테스트, `추가하지 않은 것:`, `확인하지 못한 것·리스크:`. 보고 게시 뒤에는 파일을 수정하지 않는다.
