# 모델·문맥·재시도 예산

위임 전에 루트가 한 번 읽고 작업별로 선택한다. 모델을 불러 라우팅하지 않는다. 실행기의 `TIERS`가 기본값의 원본이다. 품질 기준을 통과한 결과의 재작업 포함 토큰으로 효율을 판단한다.

## 선택
| 대상 / `--tier` | 모델 | 추론 | 사용할 때 |
|---|---|---|---|
| 루트(설계) | `opus` | high | 요구사항·계약·설계·통합 판단 |
| `implement` (기본) | `opus` | medium | 계약·샘플·쓰기 범위·검증이 정해진 일반 구현 |
| `light` | `sonnet` | medium | 정해진 치환·서식 수정·추출. 기능 설계·원인 진단은 맡기지 않는다 |
| `reason` | `opus` | high | S0의 구조 선택, 복잡한 알고리즘·진단, 보안·데이터 무결성 |
| `fallback` | `opus` | medium | Sol 6.1 사용 불가 또는 같은 유형에서 품질을 확인한 반복 구현 |
| `legacy` | `sonnet` | medium | 기존 패턴을 따르는 국소 수정에서 품질을 확인한 경우만 |

- 작은 수정은 현재 루트에서 끝낸다. 모든 일을 작업자로 쪼개면 지침·브리프·보고 비용이 더 든다.
- 일반 구현은 `implement`, 구조·알고리즘·원인에 불확실성이 크면 처음부터 `reason`. 새 근거 없이 같은 원인의 실패를 반복하면 재현·시도·diff를 붙여 `reason`으로 **한 번만** 재위임한다. 이미 `reason`이면 루트가 계약·문맥·환경을 확인하고 범위를 재분할한다. 인증·도구 오류는 모델을 바꿔 재시도하지 않는다.
- 짧은 코드라도 기능 동작·오류 처리·도메인 판단이 바뀌면 `implement` 이상이다. `light`는 기대 결과를 명확히 비교할 수 있을 때만 선택하고, 파일 수만으로 낮추지 않는다.
- 모든 모델을 차례로 거치지 않는다. 하위 버전이라고 토큰 수·비용이 작다고 가정하지 않는다. 대회 과금 기준이 다르면 실제 완료당 사용량으로 선택을 조정한다.
- `--effort low|medium|high`는 이번 실행만 바꾼다. 설계는 high, 일반 구현은 medium. low는 동일 유형에서 품질을 확인한 기계적 작업만 선택한다. `--model`만 바꾸면 tier의 effort는 유지된다.
- 순차 작업은 1개, 독립 범위가 확인되고 시간이 부족하면 2개 병렬. 3~6개는 넓은 독립 작업과 시간상 이득이 있을 때만. 같은 문제에 여러 모델을 동시에 붙여 비교하지 않는다.

## 전달과 보고
- 브리프는 40줄 안팎을 목표로 목표·쓰기 범위·계약·공통 제약·샘플·검증·기존 변경을 적는다. 관련 호출부·기존 구현·테스트 경로도 준다. 필요한 맥락은 길이 때문에 생략하지 않는다.
- 관련 모듈 지침만 `--instruction`으로 준다. 루트 지침은 실행기가 중복을 피해서 처리한다. 전체 대화·SPEC·TASKS·스킬 본문·로그를 복사하지 않는다.
- 내장 서브에이전트 대체 시 새 문맥과 위 모델·effort를 지정한다. 지원하지 않는 모델은 임의 별칭으로 바꾸지 말고 루트가 직접 처리하거나 표의 사용 가능한 대체 모델을 고른다.
- 작업자는 전달 자료를 중복해서 읽지 않되 관련 계약·호출부·테스트를 추가로 확인한다. 브리프와 원본이 다르면 추측으로 맞추지 말고 충돌을 보고한다.
- 보고는 15줄 안팎: 상태·변경 파일·검증 명령/종료 코드/핵심 출력·알고리즘/경계 사례·BLOCKER/한계·근거 경로. 실패·미검증 요구·데이터 손실 위험은 길이 때문에 생략하지 않는다.
- 루트는 diff·검증뿐 아니라 P0 수용 조건·오류 처리·관련 호출부를 확인해 DONE을 판정한다. 필요한 경계·실패 테스트를 포함하고, 동일 상태의 같은 명령만 중복 실행하지 않는다.

## 관측
```bash
python3 .claude/skills/delegate/scripts/tmux_codex.py usage --project "$PWD"
```
- Codex는 `--json`의 `turn.completed.usage`를 `usage.json`에 기록한다. 입력·캐시 입력·출력과 `total_tokens`(입력+출력)를 보여 준다. 캐시 입력은 입력에 이미 포함되므로 다시 더하지 않는다.
- `usage`는 실패·재실행을 포함한 **모든 실행**을 모델/effort별 합산한다. `--id S1`은 해당 슬라이스의 모든 시도를 집계한다. 최신 실행만 보는 `status`와 다르다.
- `unknown_runs`와 `errors`를 함께 확인한다. 실행 중·강제 종료·누락된 이벤트는 0토큰이 아니며, 완료 턴만 관측하므로 실패 중 사용량은 빠질 수 있다. 다른 CLI와 루트 세션 사용량도 별도다. 총 대회 사용량·가격 추정치가 아니다.
- `prompt_bytes`는 전달한 브리프·지침 크기이며 자동 로드 지침과 도구 출력은 제외한다. 토큰 수로 환산해 실측처럼 보고하지 않는다.
