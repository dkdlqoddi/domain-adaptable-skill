# /delegate — 슬라이스 하나를 위임한다

## 왜
"다 만들어줘"는 10분 만에 그럴듯한 결과를 주고, 남은 3시간을 수동 수정에 쓰게 만든다.
범위와 검증 방법이 적힌 브리프로 슬라이스 하나씩 위임하면, 서브에이전트는 깨끗한 컨텍스트에서 적은 토큰으로 정확히 만든다.
브리프 자체가 "쪼개고 지휘했다"는 증거다.

## 절차
1. **대상**: `$ARGUMENTS`의 ID를 `docs/TASKS.md`에서 찾는다. 설명만 있으면 새 행을 추가(쓰기 범위·검증 명령 포함)한 뒤 진행.
2. **재료** (이 파일들만 연다): 해당 슬라이스 행, `docs/CONTRACT.md`의 관련 섹션, `docs/SPEC.md`의 해당 기능 행과 비목표, `<모듈>/CLAUDE.md`, 관련 `fixtures/`. 도메인 지식은 `docs/domain/README.md` 인덱스에서 고른 파일 1개까지.
3. **브리프 작성**: [brief.template.md](brief.template.md) 형식. 계약의 샘플 값은 링크가 아니라 **값을 그대로 복사**해 넣는다(서브에이전트가 파일을 찾아 헤매지 않도록).
4. **승인**: 브리프를 보여주고 한 번만 묻는다 — "이대로 위임할까요? 줄이거나 바꿀 것이 있으면 적어주세요." 반영 후 진행.
5. **위임**: Agent 도구(general-purpose)에 브리프 전문을 전달한다. 브리프 사본을 `docs/briefs/<ID>.md`에 저장한다. `--parallel`이면 쓰기 범위가 겹치지 않는 다른 슬라이스도 같은 턴에 함께 띄우고, **모든 보고가 온 뒤에** 6번을 슬라이스마다 처리한다. 먼저 끝난 것부터 처리하면 아직 작업 중인 슬라이스의 파일을 되돌리거나 커밋에 섞는다.
6. **결과 처리**:
   - 에이전트가 보고한 검증 명령을 **루트에서 직접 다시 실행**한다. 보고만 믿지 않는다.
   - `git status --short`(또는 바뀐 파일 목록)로 쓰기 범위 밖 변경이 없는지 본다(병렬이면 함께 띄운 슬라이스들의 범위를 합쳐서). 있으면 되돌리고 이유를 묻는다.
   - 브리프에 없는 추가물(옵션·추상화·재시도·캐시·설정·로깅)이 있으면 목록으로 제거를 제안 → 사용자 결정 → 거절 내역을 `docs/DECISIONS.md`에 `/decide` 형식으로 기록.
   - `docs/TASKS.md` 상태 갱신: DONE, 또는 BLOCKED + 사유(계약 변경 요청이면 BLOCKER 표로).
   - DONE이면 커밋: `git add <쓰기 범위> docs/ && git commit -m "<ID>: <슬라이스 한 줄>"`. `git add -A`는 쓰지 않는다(테스트 캐시 같은 잔재와, 병렬일 때 다른 슬라이스의 파일이 섞인다). 슬라이스 단위 커밋이 과정의 증거이고 `/lean diff`의 기준점이다.
7. **마무리 한 줄**: 다음 슬라이스 제안. 컨텍스트가 무거워졌으면 "`/clear` 후 `/delegate <다음>`"을 권한다.

## 위임하지 않는 경우
파일 1~2개, 10분 이내의 변경은 루트에서 직접 한다(같은 브리핑·검증 규칙 적용). 위임 오버헤드가 더 크다.

## BLOCKER가 올라왔을 때 (계약 변경)
하위에서 고치게 하지 않는다. 루트에서 ① `CONTRACT.md`와 `fixtures/` 갱신 → ② `/decide`로 이유 기록 → ③ 영향받는 모듈마다 "갱신된 계약의 <섹션>을 읽고 반영하라"는 짧은 브리프로 재위임.
