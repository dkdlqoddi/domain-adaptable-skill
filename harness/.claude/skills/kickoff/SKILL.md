# /kickoff — 시작 10분: 문제를 정의한다

## 왜
과제 지시문은 일부러 짧고 모호하다. 진짜 요구사항은 현업 페르소나와의 인터뷰로만 열린다.
이 단계의 산출물은 코드가 아니라 **"무엇을 모르는지"의 목록**이다. 여기서 코딩을 시작하면 10분 만에 그럴듯한 결과가 나오고, 남은 시간은 그것을 고치는 데 쓰게 된다.

## 절차
1. **시각 확인**: `date +%H:%M`을 실행해 시작 시각을 기록한다. 총 시간은 `$ARGUMENTS`에 있으면 그 값, 없으면 6h.
2. **지시문 읽기**: `$ARGUMENTS`의 경로, 없으면 `README.md`. 그 외 파일은 열지 않는다. 디렉토리는 `ls -a` 1단계만 본다(기존 코드 유무 확인용).
3. **docs/ 뼈대**: `docs/SPEC.md`가 없으면 `mkdir -p docs && cp -rn "${CLAUDE_SKILL_DIR}/templates/docs/." docs/` 로 템플릿을 깐다(프로젝트에 이미 `docs/`가 있어도 그 안에 합쳐지고, 기존 파일은 덮어쓰지 않는다). 있으면 건드리지 않는다.
4. **과제 재정의 (3줄, 내 말로)**: ① 누가 / 어떤 상황에서 ② 무엇을 / 제출물의 형태 ③ 지시문에 명시된 제약. 지시문에 없는 내용은 쓰지 않는다. 추측은 `(가정)`.
5. **모르는 것 목록**: 아래 여섯 범주마다 "모르는 것"과 "모른 채 만들면 생기는 위험" 한 줄씩. 화면에 표로 내지 않고 6번에서 파일에만 쓴다.
   사용자 · 지금 일하는 방식 · 데이터(형식·규모) · 실행 환경 · 성공 기준 · 범위의 경계(무엇을 안 만들어도 되나)
6. **SPEC 초안**: `docs/SPEC.md`의 1절(한 줄 목표)과 7절(열린 질문)에 위 내용을 `(가정)` 표시로 적는다. 3절 기능표는 아직 비워 둔다.
7. **시간 계획**: 시작 시각 기준으로 아래 비율로 절대 시각을 계산해, 같은 표(단계·마감 시각·할 일·명령)를 `docs/TASKS.md` 맨 위에 "시간 계획" 절로 적는다. `/clear` 뒤에도 마감이 남게 하기 위해서다.
   | 단계 | 비율 | 할 일 | 명령 |
   | 1 탐색·정의 | 1/6 | 인터뷰, 내 말로 다지기, SPEC 초안. **코딩 금지** | `/interview` 반복 → `/grill` |
   | 2 계약·뼈대 | 1/6 | SPEC·입출력 샘플·슬라이스 확정, 걸어다니는 뼈대(S0) | `/spec` → `/delegate S0` |
   | 3 슬라이스 구현 | 11/24 | P0 슬라이스마다 위임·검증·정리·커밋 | `/delegate` 반복 |
   | 4 마무리·복기 | 5/24 | 통합 검증, 잔재 정리, 복기 문서, 퀴즈(선택) | `/wrapup` → `/grill quiz` |

## 하지 않는 것
- 아키텍처 제안, 기술 스택 선택, 파일 생성(docs/ 제외). 지금은 전부 이르다.
- 지시문을 그대로 요약해 "할 일 목록"으로 바꾸는 것. 그것은 인터뷰 뒤에 한다.

## 출력 (10줄 안팎)
재정의 3줄 → 단계별 마감 시각 4줄 → "모르는 것 N개를 SPEC 7절에 적었습니다." → 마지막 줄: "다음: `/interview` — 첫 질문 묶음을 만듭니다."
