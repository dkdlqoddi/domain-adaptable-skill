# 필수 지식과 심화 퀴즈 문서

`/interview`의 다지기·`quiz`, `/spec`, `/delegate`, `/wrapup`에서 해당 단계의 근거만 갱신한다.
템플릿은 [KNOWLEDGE](../kickoff/templates/docs/KNOWLEDGE.md), [QUIZ](../kickoff/templates/docs/QUIZ.md), [QUIZ-ANSWERS](../kickoff/templates/docs/QUIZ-ANSWERS.md). 기존 문서는 보존하며 필요한 절을 채운다.

## KNOWLEDGE.md — 설명할 수 있어야 하는 것
- 필수 지식 표: 개념 / 왜 필요한가 / 내 말로 설명할 내용 / 근거 / 확인 상태. 도메인 단위·현장 규칙, 입출력 계약, 자료구조, 알고리즘, 검증·실패 대응을 포함한다.
- 사실·가정·설계를 구분한다: `(인터뷰 N)`, `(samples)`, `(설계)`, `(구현 확인: 파일·함수·테스트)`, `(미확인)`. 추측을 현업 사실이나 구현 성능으로 적지 않는다.
- 핵심 처리마다 목적, 입력·출력, 처리 순서 또는 짧은 의사코드, 자료구조와 키 선택, 불변식·종료 조건을 적는다. CRUD·필터·집계도 실제 처리 과정으로 설명한다. 없는 알고리즘을 만들어 붙이지 않는다.
- 작은 입력 하나의 **입력 → 단계별 중간 상태 → 최종 출력**을 값으로 보여 준다. 중복·동률·빈 입력·잘못된 값 등 해당되는 경계 사례도 하나 이상 계산한다.
- 시간·공간 복잡도는 n·m 등 변수를 정의하고 근거 연산을 짚는다. 정렬·조회·중첩 반복·외부 호출 비용을 빠뜨리지 않는다. 평균·최악이나 실제 측정값과 추정을 구분한다.
- 현실적 대안 하나 이상과 선택 이유, 성능·정확성·단순성의 교환 관계, 입력 규모·조건이 바뀌면 선택을 바꿀 기준을 적는다.
- 실패 시나리오 / 잡아내는 테스트·픽스처·실행 명령 / 아직 검증 못 한 한계를 연결한다. 알려진 실패를 성공 근거로 쓰지 않는다.
- 구현 전에는 후보 알고리즘과 불확실성을 `(설계)`로 쓴다. 구현 후에는 관련 함수·호출부·테스트를 읽고 설계와 다른 부분을 정정한다. 진입점 한 파일만 보고 내부 동작을 단정하지 않는다.
- 역할: interview는 현장 필수 지식, spec은 알고리즘 설계, delegate는 실제 구현, wrapup은 전체 일관성과 누락을 채운다. 코드가 바뀌면 관련 퀴즈·해설도 동기화한다.

## QUIZ.md / QUIZ-ANSWERS.md
문제는 `QUIZ.md`, 모범 답·근거·채점 기준은 `QUIZ-ANSWERS.md`에 **같은 Q-ID**로 분리한다. 문서 갱신 시점과 범위(설계/구현), 관련 코드·테스트 위치를 남긴다.

| 범주 | 기본 12문항 | 마무리 16문항 |
|---|---|---|
| 도메인·단위·필수 개념 | 2 | 2 |
| 입출력·경계·현장 제약 | 2 | 2 |
| 알고리즘·자료구조 | 4 | 6 |
| 설계·대안·트레이드오프 | 2 | 3 |
| 검증·실패 진단 | 2 | 3 |

- 기본은 이해 2 + 적용 6 + 분석·설계 4문항. 마무리는 분석·설계 4문항을 더한다. 적어도 절반은 **서술·계산·실행 추적**으로 내고, 객관식에도 선택 이유를 받는다.
- 알고리즘 문항에는 실제 입력 손으로 실행하기, 불변식·정확성 설명, 시간·공간 복잡도 근거, 반례 또는 대안 비교가 각각 들어간다. 마무리에는 규모 증가 시 병목과 알고리즘 변경 후 회귀 사례를 추가한다.
- 답은 짧은 요약의 문장 복사로 끝나지 않아야 한다. 숫자·조건을 바꾼 새 사례로 추론하게 하되, 풀이에 필요한 데이터·가정·의사코드는 문제에 제공한다. 파일명·명령명·상수 암기는 출제하지 않는다.
- 각 문항에 범주·난도·평가할 능력·문제·배점을 기록한다. 정답 힌트나 정답 파일의 내용을 문제 본문에 섞지 않는다. 객관식은 그럴듯한 오답과 섞인 정답 위치를 쓴다.
- 해설은 정답만 적지 않는다: 풀이 과정, 허용되는 대안 답, 흔한 오해·반례, 근거 파일·함수·테스트, 0/1/2점 기준을 적는다. 근거가 없는 현장 규칙은 정답으로 확정하지 않는다.
- 자료가 부족하면 부족한 사실은 `미확인`으로 남기고 명시적 가정의 사례를 출제한다. 알고리즘이 확정되지 않았다면 후보 비교·샘플 추적으로 낸다. 개수만 채우는 중복 문제는 만들지 않는다.

## 진행과 채점
- 먼저 지식 문서와 전체 문제·해설 파일을 작성·갱신하고 경로만 안내한다. 학습자에게는 7문장 이내 요약 후 **4문항씩** 출제하고 매 묶음의 답을 기다린다. 요약만으로 풀리는 쉬운 문제로 낮추지 않는다.
- 답 전에는 화면에 정답·추천 표시·보기 설명을 노출하지 않는다. 도구가 힌트를 강제하면 일반 대화로 낸다. 해설 파일은 복습용이며 답을 제출한 뒤 열도록 안내한다.
- 문항별 0점(틀림·무응답), 1점(결론 일부만 맞음·근거 부족), 2점(결론과 필수 근거·계산·추적이 맞음). 이해 문항도 자기 말의 설명이 있어야 만점이다.
- 답을 받은 문항만 채점해 점수와 부족한 근거를 알리고 다음 묶음으로 간다. 마지막에 `N/24` 또는 `N/32`, 범주별 약점, 다시 볼 절·코드를 알려 준다.
- 약점에는 다른 입력·조건으로 최대 2개 보충 문제를 내고 다시 설명하게 한다. 보충 점수는 기본 점수와 분리한다. 이미 맞힌 암기 문제를 되풀이하지 않는다.
- `QUIZ.md`에는 진행 위치와 약점·재학습 경로만 남기며 답·상세 채점은 해설 파일에 둔다. 기존 회차는 유지하고 새 회차·개정 표시를 추가한다. 작업 완료·요구사항을 퀴즈 오답에 맞춰 바꾸지 않는다.
- `그만`이면 즉시 중단하고 푼 문항만 채점해 `부분 진행 N문항/총 M문항`으로 기록한다. 남은 학습은 문서에 남긴다. **퀴즈 점수·미완료는 커밋·머지·푸시·제출을 막지 않는다.**
