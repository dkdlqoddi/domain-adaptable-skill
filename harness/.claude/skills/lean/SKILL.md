# /lean — AI의 과잉 친절 쳐내기

## 왜
최신 모델은 시키지 않아도 범용 구조, 권한 처리, 추상화, 재시도를 넣는다.
그것을 비판 없이 받았는지, 요구사항에 맞게 쳐냈는지가 "인지" 점수와 사후 Q&A의 핵심이다. **쳐낸 기록 자체가 점수다.**
단, 보안·검증·데이터 보호는 쳐내는 대상이 아니다. 게으른 것이지 태만한 것이 아니다.

## 공통 기준
- 근거 = `docs/SPEC.md`의 기능 행(F#)이나 제약. 근거를 댈 수 없는 코드는 후보.
- 절대 자르지 않음: 신뢰 경계 입력 검증, 데이터 유실을 막는 에러 처리, 보안, 접근성, 하드웨어 보정, 사용자가 명시 요구한 것.
- 자주 나오는 후보: 요구 없는 설정 옵션·환경변수, 구현이 하나뿐인 인터페이스·추상 클래스, 재시도·백오프, 캐시, 락·큐, 범용 에러 래퍼, 로깅 프레임워크, 미사용 유틸, 다국어, 페이지네이션, "나중을 위한" 파라미터, 설명 과잉 주석.

## diff (기본)
1. `git diff --stat` 다음 `git diff`(스테이징 포함; 이미 커밋했으면 `git diff HEAD~1`). **diff만 읽는다.** 전체 파일은 열지 않는다.
2. 추가된 덩어리마다 표: | 파일:범위 | 무엇 | 근거(F# 또는 없음) | 제안(유지/축소/삭제) | 이유 한 줄 |
3. 축소·삭제 제안을 **한 번에 묶어** 보여주고 항목별 결정을 묻는다. 추천은 미리 표시한다.
4. 승인된 것 제거 → 해당 슬라이스 검증 명령 재실행 → `docs/DECISIONS.md`에 한 건으로 덧붙인다:
   "AI가 추가한 X를 제거/축소. 이유: SPEC 근거 없음, 현재 규모에서 불필요. 다시 넣을 조건: ..."
5. 남겨 둔 지름길은 코드에 `shortcut: <한계>, <언제 바꿀지>` 주석.

## plan <만들려는 것>
만들기 전에 요청 자체를 의심한다.
- 요청에서 SPEC 근거가 있는 부분과 없는 부분을 나눈다.
- 사다리에서 멈추는 칸을 제시한다: 없어도 되나 → 이미 있나 → 표준·플랫폼 기능 → 설치된 의존성 → 한 줄 → 최소 구현.
- "가장 작은 동작 버전"을 3줄로 제안하고 뺀 것을 나열한다. 결정은 사용자가 한다.

## all (제출 전 1회)
`git ls-files`로 파일 목록만 보고 후보를 찾는다: 미사용 파일·모듈, 구현 하나뿐인 추상화, 설정만 있고 안 쓰는 것, 샘플·데모 코드 잔재.
`grep -rn "TODO\|FIXME\|shortcut:" --exclude-dir={node_modules,.git,dist}` 로 표식을 모은다.
표로 보고, 삭제 승인은 묶어서 한 번. 결과는 `/wrapup`이 재사용한다.
