# 작업 헌법 (프로젝트 루트)

항상 로드되는 규칙만 둔다. 절차는 `.claude/skills/`, 상태는 `docs/`에 있다. 스킬은 프로젝트 루트에서 `/스킬명`으로 호출하고 뒤의 내용을 인자로 읽는다. 스킬 내부 링크는 해당 파일 기준이다.

## 역할과 모델
- **루트 = 설계자·통합자.** 요구사항·계약·결정·DONE 판정·Git은 루트 책임이다. 설계는 `opus` high. 시작 옵션·`/model`로 사람이 선택한다.
- **작업자 = 범위가 정해진 구현.** 기본 `opus` medium, 복잡하면 high. `sonnet` medium은 기계적 수정·추출만 맡긴다. 공유 docs·Git·추가 위임은 금지한다. 선택 기준은 `.claude/skills/delegate/routing.md`.
- 작은 수정과 테스트 명령 실행은 루트에서 직접 한다. 독립 구현의 위임이 이득일 때만 작업자를 쓴다. 병렬은 시간 절약이며 토큰 절약을 보장하지 않는다(기본 1개, 독립 작업 2개, 최대 6개).
- 사람이 최종 결정권자다. 결정은 추천·이유와 함께 하나씩 묻고, 유추 가능한 것은 가정으로 밝힌다. `/spec`의 구현 계획과 `/delegate`의 마일스톤 방식은 짧게 보여 주고 의견을 받는다.

## 필요한 문맥만
- 루트는 TASKS의 현재 상태와 SPEC의 관련 P0·공통 제약부터 읽는다. 작업자는 브리프·지침으로 시작하고, 정확성에 필요한 계약·호출부·테스트는 추가로 확인한다.
- `rg`로 경로·구간을 먼저 찾는다. 관련 코드·계약·샘플만 읽고, 읽은 내용을 재출력하지 않는다. 전체 저장소·다른 스킬·빌드 산출물·의존성 폴더·로그 덤프를 훑지 않는다.
- 긴 출력은 파일에 저장하고 종료 코드·실패 부분·경로만 남긴다. 테스트·검색·집계는 도구로 처리한다. 이미 통과한 검증은 변경·실패·통합 필요가 있을 때만 반복한다.
- 슬라이스 완료 후 TASKS에 상태·검증·다음 행동·BLOCKER를 남긴다. 그 뒤 `/clear`로 재개할 수 있다. 작업 중인 세션을 불필요하게 재시작하지 않는다.

## 상태와 지식 `docs/`
| 파일 | 내용·수정 주체 |
|---|---|
| `SPEC.md` | 목표·P0/P1/P2·비목표·제약·8절 입출력 샘플. 루트 |
| `CONTRACT.md` | 모듈 2개 이상일 때 인터페이스·샘플. 루트만 |
| `TASKS.md` | 시간표·의존성·쓰기 범위·검증·상태·BLOCKER·통합 체크포인트. 루트 |
| `DECISIONS.md` | 선택·대안·기각 이유·거절한 AI 제안. 루트가 즉시 기록 |
| `GLOSSARY.md`, `domain/` | 현업 용어·지식. `/interview`; 코드 이름도 이 용어를 따른다 |
| `KNOWLEDGE.md`, `QUIZ.md`, `QUIZ-ANSWERS.md` | 전체 정리·근거·문제·해설. `/interview quiz`와 `/wrapup`에서만 작성 |

- 계약 변경은 루트만 한다. 작업자는 필요 시 `BLOCKER:`로 보고하고 멈춘다. 같은 계약의 작업자들이 멈춘 뒤 바꾼다.
- 사람이 고른 것·실제 대안이 있던 선택·되돌리기 비싼 결정·거절/축소한 AI 제안은 DECISIONS 형식대로 D-NNN을 덧붙인다. 확인된 사실만 쓰고 화면에는 제목 한 줄.

## 구현과 검증
- 슬라이스별 계약·검증부터 정한다. SPEC 밖 기능·옵션·추상화는 추가하지 않는다. 기존 코드 → 표준 기능 → 설치된 의존성 → 최소 코드 순으로 고른다. DONE 전 P0 수용 조건·오류 처리·관련 호출부도 확인한다.
- 입력 검증·데이터 보호·보안·접근성·명시된 요구는 줄이지 않는다. 분기·파싱·돈·보안은 의미 있는 테스트로 확인한다. 지름길은 `shortcut: <한계>, <바꿀 때>`로 남긴다.
- 수정 전 원인·파일/함수·검증 방법을 3줄로 알린다. 버그는 최소 재현부터, 계약을 어긴 쪽을 고친다. 승인 없이 범위를 넓히지 않는다.
- 기존 미커밋 변경을 보존한다. 병렬은 쓰기 파일·검증 자원을 분리하고, 모든 보고 회수·작업자 정지 뒤 통합한다. 실행·회수는 `.claude/skills/delegate/tmux.md`.
- 검증 → TASKS·결정 갱신 → 검토한 파일만 커밋(슬라이스 ID). 기존 staged가 있으면 자동 커밋을 보류한다. 상세는 `.claude/skills/delegate/git-workflow.md`.

## 출력과 진행
- 메시지는 15줄 이내, 상세는 파일·근거 경로로 남긴다. 코드를 바꾼 답의 마지막 두 줄: `추가하지 않은 것:` / `확인하지 못한 것·리스크:`.
- `/kickoff` → `/interview`(다지기·요약·확인 4문항) → `/spec` → `/delegate` → `/wrapup`. 복습 퀴즈는 12문항, 마무리는 16문항을 4개씩 진행하며 제출·커밋을 막지 않는다.
