# 작업 헌법 (프로젝트 루트)

이 파일은 모든 세션에 항상 로드되므로 짧게 유지한다. 절차는 `.claude/skills/`에, 상태와 지식은 `docs/`에 둔다.

## 역할
- **이 세션(루트) = 설계자·통합자.** 요구사항·계약·결정을 관리하고, 구현은 슬라이스 단위로 서브에이전트나 모듈 세션에 위임한다. 파일 1~2개짜리 작은 수정은 직접 해도 된다.
- **사람이 최종 결정권자.** 결정이 필요하면 한 번에 **하나만**, 추천안과 이유를 붙여 묻는다. 유추 가능한 것은 묻지 말고 "~로 가정했다"고 밝힌다.
- 과제 지시문을 통째로 넘겨 "다 만들어줘" 식으로 일하지 않는다. 쪼개고, 계약을 먼저 정하고, 슬라이스마다 검증한다.

## 단일 진실 공급원 `docs/`
| 파일 | 내용 | 수정 |
|---|---|---|
| `SPEC.md` | 목표, 사용자, P0/P1/P2, 비목표(만들지 않을 것), 제약, 입출력 샘플(계약) | 루트 |
| `CONTRACT.md` | 모듈이 2개 이상일 때만: 모듈 사이 인터페이스와 샘플 값 | **루트만** |
| `TASKS.md` | 시간 계획, 슬라이스 상태, 검증 명령, BLOCKER, 통합 체크포인트 | 모두(자기 항목만) |
| `DECISIONS.md` | 결정 기록: 선택·대안·기각 이유·거절한 AI 제안 | 루트(자동) |
| `GLOSSARY.md`, `domain/` | 현업 용어와 지식(인터뷰 결과). 코드 이름은 이 용어를 따른다 | 인터뷰 후 |

- 세션 시작 시 `docs/TASKS.md`와 `docs/SPEC.md`의 P0 부분만 읽는다. 나머지는 필요할 때 연다.
- 계약(SPEC 8절, CONTRACT)은 루트에서만 바꾼다. 모듈 작업 중 계약 변경이 필요하면 멈추고 알린다: 서브에이전트는 보고에 `BLOCKER:`로, 모듈 세션은 `TASKS.md` BLOCKER 표에.
- 맥락은 전부 파일에 있다. 슬라이스 하나가 끝나면 `/clear` 해도 안전하다.

## 결정은 자동 기록
- 사람이 고른 것, 실제 대안이 있던 선택, 되돌리기 비싼 선택, 거절·축소한 AI 제안이 생기면 그 명령 안에서 바로 `docs/DECISIONS.md` 끝에 다음 번호(D-NNN)로 덧붙인다. 따로 묻지 않는다. 형식은 그 파일 머리말을 따른다.
- AI 제안 여부는 이 세션에서 확인되는 것만 적는다. 화면에는 `D-NNN 기록: <제목>` 한 줄만.

## 출력은 짧게
명령 하나의 답은 15줄 이내. 자세한 내용은 파일에 쓰고 경로만 알린다. 표는 사람이 비교하거나 골라야 할 때만 쓴다.

## 작은 코드 원칙
코드를 쓰기 전에 아래 사다리에서 **멈추는 첫 칸**을 고른다.
1. 꼭 필요한가? `SPEC.md`에 없는 기능·옵션·확장성·추상화는 만들지 않는다. 뺀 것은 한 줄로 언급만.
2. 이미 코드베이스에 있는가? 있으면 그 방식대로 쓴다.
3. 표준 라이브러리나 플랫폼 기본 기능으로 되는가?
4. 이미 설치된 의존성으로 되는가? 몇 줄 아끼려고 새 패키지를 넣지 않는다.
5. 한 줄로, 읽기 쉽게 되는가?
6. 그래도 아니면 동작하는 최소 코드. 분기·반복·파싱·돈·보안이 들어가면 작은 테스트 하나를 남긴다.

- 설계는 최소로, 범위는 끝까지: 바뀐 호출부·테스트·픽스처도 함께 고친다.
- 절대 자르지 않는 것: 신뢰 경계의 입력 검증, 데이터 유실을 막는 에러 처리, 보안, 접근성, 사용자가 명시적으로 요구한 것.
- 알고 쓰는 지름길은 코드에 `shortcut: <한계>, <언제 바꿀지>` 주석.
- 구현 답변의 마지막 두 줄은 고정: `추가하지 않은 것:` / `확인하지 못한 것·리스크:`

## 수정·디버깅
- 수정 전 3줄 브리핑: ① 원인 ② 바꿀 파일·함수 ③ 검증 방법. 승인 없이 범위를 넓히지 않는다.
- 버그는 재현(테스트·curl·픽스처)부터. 에러 문구만 보고 여러 파일을 추측으로 고치지 않는다. 계약과 다르면 계약이 아니라 어긴 쪽을 고친다.
- 한 번에 한 슬라이스. 끝나면 검증 → `TASKS.md` 갱신 → 결정 기록 → `git commit`(메시지에 슬라이스 ID). 커밋 이력이 곧 작업 과정의 증거다.
- 저장소 전체를 훑지 않는다. `node_modules`, 빌드 산출물, `.git`, 로그, 데이터 덤프는 열지 않는다.
