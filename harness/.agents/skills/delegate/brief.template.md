## 작업 순서
1. 검증 명령(또는 실패하는 테스트)을 먼저 만든다 → 2. 동작하는 최소 구현 → 3. 검증 통과 → 4. 보고
문서의 중복 읽기는 피하되 정확성에 필요한 근거는 확인한다. 새 근거 없이 같은 원인의 실패를 반복하면 재현·시도·남은 원인을 BLOCKED로 보고한다.
단계가 바뀌거나 막히면 전달받은 `progress` 명령으로 현재 단계·상황을 게시한다. 긴 작업은 가능한 도구 호출 사이에 약 60초마다 갱신한다. 부모가 `wait`·`status`로 확인한다.
