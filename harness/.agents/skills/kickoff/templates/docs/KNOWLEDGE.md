# KNOWLEDGE — 필수 지식과 알고리즘

> 현장 사실·가정·설계·구현 확인을 구분한다. 문서·함수·테스트로 근거를 연결하고 변경 시 갱신한다.

## 0. 전체 내용 한눈에
사용자가 처음부터 끝까지 자기 말로 설명할 수 있도록 각 행을 채운다. 구현 전에는 설계·미확인으로 표시한다.

| 주제 | 정리할 내용 | 근거·확인 상태 |
|---|---|---|
| 문제와 목표 | 누구의 어떤 불편을 해결하며, P0·성공 기준·비목표는 무엇인가 | |
| 도메인과 제약 | 핵심 용어·단위·현장 규칙·실행 환경에서 무엇을 지켜야 하나 | |
| 전체 동작 | 대표 입력이 어떤 진입점·모듈·계약을 거쳐 저장·출력되며, 실패 시 어떻게 되나 | |
| 핵심 처리 | 실제 알고리즘·자료구조·불변식은 무엇이며, 왜 결과가 맞나 | |
| 선택과 대안 | 무엇을 왜 선택·거절했고, 어떤 조건에서 선택을 바꾸나 | |
| 실행과 검증 | 어떻게 실행하고 무엇으로 확인했나. P0 완료·검증 실패·미확인은 각각 무엇인가 | |
| 한계와 다음 행동 | 남은 가정·지름길·미완료가 사용자에게 어떤 영향을 주며, 다음에 무엇을 확인하나 | |

대표 입력 → 중간 상태 → 출력의 상세 값은 3절, 주제·P0별 문제 연결은 QUIZ.md의 범위표를 참조한다.

## 1. 반드시 설명할 지식
| 개념 | 왜 필요한가 | 내 말로 설명할 내용 | 근거 | 확인 상태 |
|---|---|---|---|---|

## 2. 핵심 알고리즘과 자료구조
각 핵심 처리마다 목적·입출력, 처리 단계/의사코드, 자료구조·키, 불변식·종료 조건, 근거 함수·테스트를 적는다.
구현 전은 `(설계)`, 구현 후는 `(구현 확인)`으로 구분한다.

## 3. 손으로 따라가는 실행 예
정상 입력과 경계 입력 각각: 입력 값 → 단계별 중간 상태 → 출력 값. 기대 결과의 근거를 붙인다.

## 4. 복잡도와 대안
입력 크기 변수, 시간·공간 복잡도와 근거 연산, 대안, 선택 이유, 선택을 바꿀 조건. 측정값과 추정을 구분한다.

## 5. 실패·검증·한계
| 실패/경계 사례 | 검증 명령·테스트·픽스처 | 확인 결과·미확인 한계 |
|---|---|---|

## 6. 아직 설명 못 하는 것
현업 확인이 필요한 질문, 학습할 개념, 다음에 확인할 코드·테스트 위치. 퀴즈 뒤에는 설명 확인·보충 필요·미응답을 구분하고, 약점마다 다음 학습 행동 하나를 적는다.
