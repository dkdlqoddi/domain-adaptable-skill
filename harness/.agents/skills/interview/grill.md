# 다지기 → 요약 → 퀴즈

`$interview`가 인터뷰를 마칠 때 이 순서로 한다. `$interview quiz`와 `$wrapup`은 읽기·학습 문서 → 요약 → 퀴즈만 한다.
인터뷰 답을 AI가 정리만 하면 문서는 쌓여도 내 머릿속은 비어 있다. 용어와 경계를 한 번에 하나씩 캐물어 내 말로 정하고, 정해진 것은 바로 기존 문서에 적는다.
필수 지식·문제·해설을 문서로 남긴다. 퀴즈는 복습이지 관문이 아니다.

## 읽기
`docs/GLOSSARY.md`, `docs/domain/README.md`(인덱스·아직 모르는 것), `docs/SPEC.md` 1·3·4·7·8절, `docs/DECISIONS.md` 제목 줄(`rg '^## D-'`). 있으면 `docs/KNOWLEDGE.md`, `docs/RETRO.md` 1·4절. 이미 읽은 것은 다시 열지 않는다.
domain 파일은 필요한 것만 연다. 알고리즘 설명에 필요한 실제 함수·호출부·테스트·샘플을 확인한다. 구현 전에는 설계와 가정을 구분한다.

## 빈틈 찾기
아래 순서로 후보를 모은다.
1. 용어: GLOSSARY에 없는 말, 한 말이 두 뜻, 두 말이 한 뜻.
2. 단위와 경계: 무엇을 하나로 세나(예: 로트·웨이퍼·다이), 몇 대 몇인가, 어디까지가 범위인가.
3. 시나리오: 경계에 걸리는 구체적 사례 하나("같은 웨이퍼가 같은 공정을 두 번 지났다면?").
4. 가정: SPEC이나 계약을 바꿀 수 있는 `(가정)`.
5. 모순: 문서와 샘플·코드가 다르게 말하는 곳.
샘플·코드로 답이 나오는 것은 묻지 않고 확인해서 `(samples)`로 적는다. SPEC이나 계약을 바꾸는 것부터 묻는다.

## 캐묻기 (한 번에 하나)
- 질문은 현업의 말로 한 문장. 추천 답과 근거(파일·샘플)를 붙이고 답을 기다린다. 현재 모드에서 사용할 수 있는 질문 도구가 있으면 선택지로 낸다: 추천을 첫째에, 대안 1~2개, "모름 — 페르소나에게 묻기". 도구가 없거나 현재 모드에서 사용할 수 없으면 일반 대화로 묻는다.
- GLOSSARY와 다른 뜻으로 쓰면 바로 짚는다: "GLOSSARY에는 X가 A인데 지금 B로 쓰셨습니다. 어느 쪽인가요?" 뭉뚱그린 말에는 정확한 용어를 제안한다.
- 답을 받으면 모아 두지 말고 바로, **한 곳에만** 적는다. 같은 내용을 여러 파일에 되풀이하지 않는다:
  - 용어 → GLOSSARY 한 줄. 뜻은 "무엇인지" 한 문장, 피할 말은 유사어·주의 칸에. 구현 세부는 쓰지 않는다.
  - 사실·경계·규칙 → 맞는 `docs/domain/<주제>.md` 하나에 불릿 + `(다지기)`. 현장 사실을 추측으로 답했으면 `(가정)`.
  - 결정 → AGENTS.md 규칙대로 `DECISIONS.md`. 그 결정이 용어의 뜻을 바꿀 때만 GLOSSARY 그 줄에 D-번호를 단다.
  - 모름 → `domain/README.md` "아직 모르는 것"에 `→ 페르소나` 한 줄. 다음 `$interview`가 먼저 묻는다.
- SPEC은 고치지 않는다(반영은 `$spec`이 한다).
- 멈춤: 중요한 빈틈을 최대 6문항까지 하나씩 묻는다. 빈틈이 없거나 사람이 "그만"이면 즉시 멈춘다. 계약을 바꿀 미확인은 남겨 두고 후속 인터뷰로 넘긴다.
- 끝나면 `domain/README.md`의 요약 줄을 한 번 고치고, 표 아래에 `다지기: <HH:MM>` 한 줄을 남긴다. 다음 `$interview`는 이 줄을 보고 다지기를 되풀이하지 않는다.

## 학습 문서 → 요약
[learning.md](learning.md)에 따라 `docs/KNOWLEDGE.md`, `docs/QUIZ.md`, `docs/QUIZ-ANSWERS.md`를 작성·갱신한다. 인터뷰 단계라도 알고리즘 후보·샘플 추적·복잡도를 `(설계)`로 구분해 포함한다.
문서만 보고 **7문장 이내**로 쓴다. 넘으면 덜 중요한 사실을 뺀다. 지금 일하는 방식, 핵심 문제, 핵심 용어와 단위, 제약, 성공 기준, 결정과 비목표(있으면), 아직 모르는 것.
- 한 문장에 사실 하나, 25어절 이내. 파일 경로·코드·화살표 금지. 피할 수 없는 기술 용어는 쉬운 말 뒤 괄호에.
- 요약은 큰 흐름만 다룬다. 심화 문제에 필요한 지식은 KNOWLEDGE에, 계산할 입력·가정은 문제에 제공한다.

## 퀴즈 (기본 12문항, 마무리 16문항)
- [learning.md](learning.md)의 범주별 배분·난도·채점 기준을 따른다. 적어도 절반은 서술·계산·실행 추적이며 객관식도 이유를 받는다. 실제 알고리즘·복잡도·반례·대안·실패 진단을 검증한다.
- 4문항씩 제시하고 답을 기다린다. 정답은 답 제출 전 화면에 쓰지 않는다. 채점 후 다음 묶음, 마지막에는 약점별 보충 최대 2문항. 요약 7문장·메시지 15줄 제한 때문에 문항 수를 줄이지 않는다.
- 최종 점수 `N/24` 또는 `N/32`와 다시 볼 문서·코드를 안내하고 학습 문서에 진행·해설을 남긴다. `그만`이면 남은 문제는 문서로 남기고 중단한다.
- **관문이 아니다.** 점수·퀴즈 미완료와 상관없이 커밋·머지·푸시·제출을 막거나 미루지 않는다. 다시 풀려면 `$interview quiz`.

## 출력 (메시지마다 15줄 이내)
- 캐묻는 중: 질문 하나. 직전 답을 적었으면 앞에 `기록: <파일들>` 한 줄.
- 끝: 요약 → 퀴즈 → 채점 → 마지막 줄 "다음: `$spec`". 페르소나에게 넘긴 것이 있으면 그 수와 "`$interview`로 질문 묶음을 만들 수 있습니다(시간이 없으면 `$spec`)". `quiz`나 `$wrapup`에서 불렀으면 마지막 줄은 부른 쪽을 따른다.
