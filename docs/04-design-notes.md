# 설계 노트 — 왜 이렇게 만들었나

## 1. 참고한 두 모델과 차용한 것
### grill-with-docs (Matt Pocock, mattpocock/skills)
- **원형.** 계획을 날카롭게 만드는 집요한 인터뷰. 한 번에 질문 하나, 추천 답을 붙이고, 유추 가능한 것은 묻지 않는다. 합의된 용어는 `GLOSSARY.md`에 즉시, 되돌리기 비싸고 실제 대안이 있던 결정만 `docs/adr/NNNN-*.md`로 기록한다. 글로서리에 구현 세부는 쓰지 않는다.
- **차용.** `GLOSSARY.md`(규칙 동일), "한 번에 하나 + 추천안"(루트 CLAUDE.md 역할 절에 상시 규칙으로), "유추 가능한 것은 가정 표시"(동일), ADR 선별 기준(`DECISIONS.md` 머리말과 CLAUDE.md "결정은 자동 기록"에).
- **다른 점.** 인터뷰 대상이 사용자가 아니라 **페르소나 에이전트**이고 사용자는 중계자다. 그래서 `/interview`는 답을 붙여 실행하면 소화하고 다음 질문까지 낸다(처음에는 질문·소화 두 모드로 나눴다가 리허설 3에서 합쳤다). 지식은 `docs/domain/<주제>.md` + 인덱스로 분리해 모듈이 필요한 파일 하나만 열 수 있게 했다. ADR은 폴더 대신 `DECISIONS.md` 한 파일에 D-NNN으로 쌓는다. 6시간 규모에서는 파일 하나가 탐색·토큰 비용이 가장 낮다.
- **사람에게 직접 묻는 원형은 다지기로.** `/interview`가 인터뷰를 마치면 이어서 한다. 처음에는 `/grill`로 따로 두었다가 합쳤다(9·10절).

### ponytail (Dietrich Gebert)
- **원형.** "게으른 시니어 개발자" 페르소나. 쓰기 전에 영향 범위를 파악하고, 사다리(필요한가 → 코드베이스에 있나 → 표준 라이브러리·플랫폼 → 설치된 의존성 → 한 줄 → 최소 구현)를 내려가며 멈추는 첫 칸을 고른다. 입력 검증·데이터 유실 방지·보안·접근성은 절대 자르지 않는다. 분기·반복·파싱·돈·보안 로직에는 작은 테스트 하나. 답변 끝에 뺀 것과 리스크. 한계를 아는 지름길은 `shortcut:` 주석. 제작자 벤치마크는 코드 53%·토큰 45% 감소, 외부(JetBrains) 재현은 코드 15%·비용 10% 감소.
- **차용.** 위 규칙 전부를 루트 `CLAUDE.md` "작은 코드 원칙" 12줄에 압축했다. 감사 절차는 `/delegate`(슬라이스마다 diff)와 `/wrapup`(제출 전 저장소 전체)에 넣었다(처음에는 `/lean`으로 분리했다가 리허설 3에서 합쳤다).
- **배치 결정.** 스킬로만 두면 자동 발동이 안 되는 경우가 많다(외부 테스트 10세션 중 0회). ponytail 플러그인도 그래서 세션 시작 시 규칙을 주입한다. 우리는 항상 로드되는 CLAUDE.md에 두었다.
- **추가.** "쳐낸 것을 `DECISIONS.md`에 기록"하는 단계(지금은 명령이 자동으로 기록). 원형에는 없는, Cofa Probe의 인지 점수와 Q&A를 위한 단계다.

## 2. 토큰 설계
### 세 층의 로딩
| 층 | 무엇 | 언제 | 크기 (check.sh 근사) |
|---|---|---|---|
| 1 항상 | 루트 `CLAUDE.md` | 매 세션 | 80줄 이하, 현재 근사치는 check.sh |
| 1 항상 | 스킬 설명 5개 | 매 세션이지만 전부 `disable-model-invocation: true` | **0** |
| 2 호출 시 | `SKILL.md` 본문 | `/명령` 입력 시, 그 세션에 유지 | 120줄 이하 |
| 3 필요 시 | 참고 파일 (Git 절차 포함) | 본문이 "언제 열지"를 명시 | 파일마다 80줄 이하 |
| 조건부 | 모듈 `CLAUDE.md` | 모듈이 여럿일 때, 그 폴더의 파일을 읽거나 쓸 때 | 40줄 이하 |

### 왜 전부 사용자 호출 전용인가
- **토큰.** 설명이 컨텍스트에서 완전히 제외된다(공식 문서: "Description not in context, full skill loads when invoked").
- **통제.** 사람이 단계를 호출하는 것 자체가 로그에 남는 지휘의 증거다. 모델이 알아서 `/spec`을 실행하면 "AI에 끌려갔다"로 읽힐 수 있다.
- **단순함.** 초보자는 "순서대로 5개"만 기억하면 된다. 각 명령의 `다음:` 안내가 다음 명령을 알려준다.

### 세션 메모리는 파일로
- `docs/` 4종(모듈이 여럿이면 CONTRACT까지 5종) + `domain/`이 외부화된 메모리다. `/clear` 뒤 새 세션은 CLAUDE.md + TASKS + SPEC P0만 읽는다.
- 서브에이전트 브리프에는 계약의 샘플 값을 링크가 아니라 **값으로 복사**한다. 파일을 찾아 헤매는 토큰을 없앤다.
- `domain/README.md` 인덱스가 있어 "무엇을 아는지"를 한 줄 요약만으로 파악한다.

## 3. 도메인 적응성
- 하네스 어디에도 web/frontend/backend 가정이 없다. 계약은 API·CLI·파일 포맷·함수·상태 전이 중 택일한다.
- 예시 3종(웹, 데이터 CLI, EDA 툴 드라이버)을 `spec/contract-examples.md`에 두었다. 특히 외부 도구를 부르는 모듈의 `--dry-run` + 샘플 로그 픽스처 패턴은 상용 툴이나 라이선스가 없는 환경에서도 개발·검증을 가능하게 한다(모듈 지침 템플릿에 한 줄로 남겼다).
- 도메인 지식은 당일 인터뷰로 채우고, 사전에 공개되면 `templates/docs/domain/primer.md`로 미리 채운다.

## 4. 의도적으로 하지 않은 것
| 안 한 것 | 이유 |
|---|---|
| 훅(PreToolUse 등)으로 규칙 강제 | 환경마다 셸·권한이 달라 당일 실패 위험. 규칙은 CLAUDE.md로, 강제는 사람이 |
| 동적 컨텍스트 주입 `` !`cmd` `` | 명령이 실패하면 스킬 전체가 중단된다. 대신 절차 1단계에서 `date`를 실행하게 했다 |
| 모듈 종류별 커스텀 서브에이전트(`.claude/agents/`) | 파일이 늘고 이점이 작다. 브리프 + general-purpose로 충분 |
| ADR 폴더, 멀티 컨텍스트 글로서리 | 6시간 규모에는 과하다. 그 자체가 과잉 설계 |
| 프레임워크 보일러플레이트 | 도메인을 모른다. 사다리 2~4칸(코드베이스·표준·설치된 의존성)이 대신한다 |
| 모델 자동 호출 스킬 | 토큰과 통제 이유. 위 2절 |
| 경로 스코프 규칙(`.claude/rules/`) | 모듈별 `CLAUDE.md`가 같은 역할을 하고, 모듈 폴더에서 세션을 띄울 때도 확실히 로드된다 |

## 5. 확장하는 법
- **스킬 추가.** `harness/.claude/skills/<name>/SKILL.md`. `name`은 폴더명과 같게, `disable-model-invocation: true`, 120줄 이하, 참고 파일은 "언제 열지"와 함께 링크. `scripts/check.sh`로 확인.
- **규칙 추가.** 루트 CLAUDE.md는 80줄 한도. 넘으면 특정 폴더에서만 필요한 규칙은 `<모듈>/CLAUDE.md`로, 특정 파일 종류에서만 필요한 규칙은 `.claude/rules/<topic>.md`에 `paths:` 프런트매터로.
- **도메인 사전 준비.** `templates/docs/domain/primer.md` 추가. 설치·패키징에 자동 포함된다.
- **검증.** `scripts/check.sh`는 정적 검사와 임시 프로젝트의 설치·변환·ZIP 회귀 검증을 수행한다. 그 뒤 빈 과제에서 선택한 CLI로 전체 흐름을 리허설한다. 바이트 기반 토큰 추정은 시스템·도구·대화 비용을 포함하지 않는다.

## 6. 리허설 결과 (2026-10-23)
모의 과제 "인터뷰 연습 도우미"(지시문 5줄)로 9개 명령을 순서대로 돌렸다. 페르소나 답변 2회차는 가공했고, 사람이 없는 헤드리스 실행이라 "결정은 추천안으로 진행하고 (가정) 표시"라는 리허설 지시를 인자로 붙였다. 산출물 전체는 `examples/rehearsal-interview-coach/`.

| 명령 | 나온 것 |
|---|---|
| `/kickoff` | 재정의 5줄, 모르는 것 6범주, 실제 시각 기준 시간표. SPEC 1·7절과 TASKS 상단에 기록 |
| `/interview` ×2 | 사다리 ① 질문 5개 → digest로 domain 4파일·GLOSSARY 8용어·SPEC 후보 4개. 지시문과 담당자 말이 갈리는 지점을 추천안과 함께 사람에게 넘김 |
| `/spec all` | P0 2개, 비목표 13개(각각 인터뷰 근거), 모듈 2개 계약과 픽스처 8개, 결정 5건 |
| `/workspace all` | 모듈 CLAUDE.md 22줄×2, 슬라이스 S0~S5, 감사 6항목 통과 |
| `/delegate S0` | 브리프 저장 → 서브에이전트 → 루트 재검증 → 범위 확인 → DONE 커밋. 서버 106줄, 테스트 55줄, HTML 24줄 |
| `/verify all` | 테스트·스모크·curl 8종·손상 파일 3종·브라우저 2장면. 체크포인트 기록 |
| `/lean diff` | 덩어리 13개를 SPEC·CONTRACT와 대조, 제거 0건. 브리프의 "하지 말 것"이 사전 차단했음을 D-010으로 기록 |
| `/decide` | D-001을 형식대로 추가, 빠진 대안은 `(추정)`으로 유추 |
| `/wrapup all` | 실행 README 3단계, RETRO 9절 85줄. P0 미완을 "제출 불가"로 명시 |

리허설로 고친 것: 재설치 시 CLAUDE.md 중복 로드, 기존 `docs/`가 있을 때 `docs/docs/` 중첩, `/lean diff`가 새 파일(untracked)을 못 보던 문제, 슬라이스 단위 커밋 규칙 부재, `install.sh --force`의 `docs/` 덮어쓰기, TASKS 칸 길이 무제한, `/verify`의 브라우저 자동화 도구 활용.

## 7. 리허설 2 결과 (2026-10-26)
1차에서 못 해 본 것을 채우려고 웹이 아닌 과제 "회귀 결과 정리 도우미"(반도체 검증 로그 → 팀 채널 글, CLI)로 다시 돌렸다. 숨은 사실만 아는 별도 AI를 페르소나로 두고, 사용자 플러그인을 끈 깨끗한 환경에서 명령마다 새 세션으로 실행했다. 60분 만에 P0 3개와 P1 1개를 끝냈고, 하네스 비용은 약 $14.7이었다. 상세는 `examples/rehearsal-2-regress-triage/README.md`.

- **된 것.** 단일 모듈 선택(분할하지 않음), 샘플에서 숨은 요구 발견, 판단 요청을 매번 하나씩 추천과 함께, `/lean`의 실제 수정 2회, 시연에서 나온 새 요구를 계약 변경(CONTRACT v2)으로 처리.
- **병렬 위임.** 단일 모듈이라 본편에서는 쓸 수 없어 별도 프로젝트로 시험했다. 고친 규칙대로 모든 보고를 기다린 뒤 처리했고, 커밋이 슬라이스별로 깨끗하게 나뉘었다.
- **확인하지 못한 것.** `/verify`의 실패 처리(실제 버그가 안 나옴). 사람이 직접 하는 리허설.

리허설 2로 고친 것:
- 샘플 데이터를 보지 않던 `/interview` → 샘플을 먼저 훑고, 아무도 말하지 않은 예외는 질문으로 바꾼다.
- 새 세션에서는 앞 세션의 채팅 내용을 볼 수 없다. 그래서 `/decide`가 AI 제안 여부를 추측했고, 판단 대기 항목이 사라졌다 → 근거가 없으면 묻고, 판단 대기는 `domain/README.md`에 남긴다.
- `git add -A`가 잔재를 담고 병렬 슬라이스를 섞는 문제 → 커밋은 `git add <쓰기 범위> docs/`, `/lean diff`는 `git add -N <쓰기 범위>`.
- 서브에이전트가 `docs/TASKS.md`를 함께 고치는 문제 → 에이전트는 `docs/`를 고치지 않고 BLOCKER는 보고에 적는다.
- 그 밖: zip의 `INSTALL.txt`를 zip 주석으로 옮김, `/workspace` 마지막 안내를 고정값에서 첫 TODO 슬라이스로.

## 8. 리허설 3 결과와 단순화 (2026-10-27)
사람이 직접 처음 보는 반도체 과제(`examples/rehearsal-3-yield-kit/`)로 해 봤다. 18분 동안 명령을 6번 입력했고(`/kickoff 2h` → `/interview` → digest → `/interview` → digest "알아서 채워주세요" → `/spec` 도중 중단), "동작이 너무 복잡하다"는 결론이 나왔다.
- 명령마다 답이 1,300~1,700자였고, 18분 사이 docs 파일 8개가 바뀌었다. 따라 읽기 어렵다.
- 인터뷰 한 회차에 명령 2번(질문, digest)과 복사 2번이 필요했다. 2회차에서 손을 놓았다.
- 결정 2건은 `/decide` 없이 digest와 `/spec`이 직접 적었다. 별도 명령이 필요 없었다.
- 4시간 기준으로 명령을 30~40번 입력해야 하는 구조였다.

바꾼 것(명령 9개 → 5개):
| 전 | 후 |
|---|---|
| `/interview` + `/interview digest` | `/interview <답>` 하나: 정리하고 다음 질문까지 |
| `/spec` + `/workspace` | `/spec`: SPEC·입출력 샘플(8절)·슬라이스·커밋까지. CONTRACT와 모듈 지침은 모듈이 2개 이상일 때만. 아키타입 분류는 뺐다 |
| `/delegate` + `/verify` + `/lean diff` | `/delegate`: 위임 → 루트 재검증·회귀 확인 → diff 정리 → 커밋 |
| `/verify all` + `/lean all` + `/wrapup` | `/wrapup check`: 통합 검증·저장소 전체 정리·실행 README |
| `/decide` | 없앰. 결정이 생긴 명령이 `DECISIONS.md`에 자동 기록 |
| 출력 길이 제한 없음 | 명령 하나의 답은 15줄 이내(CLAUDE.md), 명령마다 출력 형식 지정 |

- 유지한 것: `domain/` 주제별 파일 분리(사용자 결정), 인터뷰 사다리, 브리프 승인 1회, 슬라이스 단위 커밋.
- 잃은 것: 매시간 통합 확인(슬라이스마다 회귀 확인으로 대신), 기존 코드베이스의 아키타입 분석, 만들기 전 `/lean plan`.
- 비용: 항상 로드되는 CLAUDE.md가 44줄(~950 토큰)에서 51줄(~1,100 토큰)로 늘었다. 결정 자동 기록과 출력 제한 규칙 때문이다.
- 확인: 작은 모의 과제("설비 알람 정리 도우미", 지시문 3줄)로 새 흐름을 깨끗한 환경에서 돌렸다. `/kickoff 1h` → `/interview` + 답 3회 → `/spec` → `/delegate S0`(추천대로 루트에서 직접) → `/delegate S1`(서브에이전트) → `/wrapup check`. 비용은 약 $2.4.
  - 명령 답은 358~962자였다(이전 1,300~1,700자).
  - 답을 붙인 `/interview`가 기록과 다음 질문을 한 번에 냈고, 결정 5건이 자동으로 기록됐다.
  - 모듈이 1개라 `CONTRACT.md` 없이 SPEC 8절과 fixtures로 갔다. `/spec`·`/delegate`·`/wrapup`이 각각 커밋했다.
  - `/wrapup check`는 아직 TODO인 S2와 약한 검증 명령을 잡아냈다.
  - 이 확인으로 두 가지를 고쳤다. `/spec` 출력에서 완료 기준을 뺐다(21줄로 한도 초과였다). `/wrapup check`가 추적되지 않는 잔재(`__pycache__`)도 보게 했다.

## 9. `/grill` 추가: 내 말로 다지고, 요약하고, 퀴즈로 확인 (2026-10-27)
> 10절에서 `/interview`(다지기)와 `/wrapup`(퀴즈)으로 합쳤다. 아래는 따로 있던 때의 기록이다.

요청: grill-with-docs처럼 도메인 지식을 문서로 관리하고, blindspot-flow처럼 내용을 요약해 마지막에 퀴즈로 확인하기. 단, 퀴즈가 main 머지·푸시의 관문이 되면 안 되고, 문서 산출물은 최소로 한다.
- **왜 새 명령인가.** `/interview`는 페르소나에게 물을 질문 묶음을 만든다. `/grill`은 사람에게 직접 하나씩 묻는다. 묻는 상대도 방식도 달라서 한 명령에 넣으면 모드가 생긴다. 그래서 따로 두고 선택으로 했다.
- **grill-with-docs(grilling + domain-modeling)에서 가져온 것.** 한 번에 하나, 추천 답 붙이기, 코드·샘플로 답이 나오면 묻지 않기. GLOSSARY와 다르게 쓰는 말과 뭉뚱그린 말 짚기, 경계에 걸리는 사례로 시험하기. 답은 그 자리에서 기록하고, 결정은 되돌리기 비싼 것만 남긴다.
- **다른 점.** CONTEXT.md나 ADR 폴더를 새로 만들지 않고, 기존 `GLOSSARY.md`·`domain/`·`DECISIONS.md`에만 쓴다. 한 답은 한 곳에만 쓰고, SPEC 반영은 `/spec`에 맡긴다. 사람이 모르는 현장 사실은 "아직 모르는 것"에 `→ 페르소나`로 남기고, 다음 `/interview`가 그것부터 묻는다. 시간 때문에 6문항에서 멈추고, 1단계 마감이 지났으면 3문항에서 멈춘다.
- **blindspot work-report에서 가져온 것.** 퀴즈에 필요한 사실은 전부 요약에 넣는다. 한 문장에 사실 하나, 25어절 이내로 쓴다. 보기는 40자 이내로 쓰고, 그럴듯한 오답을 넣고, 정답 위치를 섞는다. 암기형 문항은 내지 않고, 틀린 문항은 해설한다.
- **관문을 없앤 방법.** 퀴즈는 HTML 파일 대신 터미널에서 낸다. Claude Code의 질문 도구를 쓰고, 도구가 없으면 `1a 2c` 형식으로 답을 받는다. 결과는 파일에 남기지 않는다. 어떤 명령도 퀴즈 통과를 기다리지 않고, 훅도 쓰지 않는다. `/wrapup retro`는 커밋까지 끝낸 뒤 `/grill quiz`를 선택으로 안내만 한다.
- **확인.** 리허설 2 문서를 넣은 빈 프로젝트에서 헤드리스로 돌렸다(합계 약 $1.4).
  - `/grill quiz`: 요약 7문장과 4문항을 냈다. 채점 전에는 정답을 보이지 않았고, 파일도 바꾸지 않았다. 채점에서는 틀린 문항만 정답과 이유, 다시 볼 곳을 보였다.
  - `/grill`: 문서와 계약이 어긋난 곳을 찾아 한 문항씩 물었다. 비교 기준이 "지난 게시 글"로 적혀 있는데, 도구는 마지막 실행을 기준으로 쓰고 있었다. "모름"으로 답한 문항은 페르소나 몫으로 넘겼고, "그만"이라고 하자 요약·퀴즈·채점으로 끝냈다.
  - 고친 것: 첫 시험에서 답 하나가 파일 5곳에 반복 기록됐다(SPEC 포함). 그래서 규칙을 "한 곳에만 쓰고, SPEC은 고치지 않고, 인덱스는 끝에 한 번"으로 바꿨다. 다시 돌리자 사실은 1곳에만 들어갔고, 나머지 2곳은 낡은 "미확인" 표시를 고친 것이었다.
- **확인하지 못한 것.** 대화형 세션에서 질문 도구(선택지 화면)로 낼 때의 모습. Codex에서 `$grill`이 동작하는지.

## 10. 다지기를 `/interview`에 합치고 단계 더 줄이기 (2026-10-27)
사용자 질문: "interview와 grill을 합치는 게 더 효율적이지 않을까요?" 두 명령은 같은 문서를 읽고 같은 곳에 썼고, `/interview`도 모순은 이미 사람에게 하나씩 물었다. 9절에서 따로 둔 이유(묻는 상대가 다르면 모드가 생긴다)는 시간 순서로 풀었다. 페르소나 인터뷰가 끝난 뒤에만 사람에게 묻는다. 같은 김에 흐름 전체를 다시 훑어 줄일 단계를 사용자가 골랐다.

| 전 | 후 |
|---|---|
| `/grill` (선택) | `/interview`가 멈추는 기준에 닿으면 이어서 다지기 → 요약 → 퀴즈. 절차는 `interview/grill.md`에 두고 그때만 읽는다(본문에 다 넣으면 `/interview`를 부를 때마다 약 1,200토큰이 더 실린다). 다지기는 기본 3문항이고, SPEC·계약을 바꿀 빈틈이 남으면 더 묻는다. `domain/README.md`에 `다지기:` 줄이 있거나 DONE 슬라이스가 있으면 다시 하지 않는다 |
| `/grill quiz` | 마감 때는 `/wrapup`이 낸다. 제출 뒤 복습은 `/interview quiz` |
| `/grill <주제>` | 없앴다. `/interview <글>`이 페르소나의 답인지 주제인지 구분할 수 없다 |
| 인터뷰는 사다리가 차면 멈추고, 1단계 마감에 끊고, "더 물어볼 수 있다"로는 계속하지 않았다 | 중요한 모르는 것(P0·비목표·입출력·성공 기준을 바꿀 것)이 남으면 보충 묶음으로 더 묻는다. 회차 제한은 없다. 마감이 지나면 `1단계 마감 +N분`을 보이고 사람이 정한다(사용자 요청: "필요하다면 더 길어질 수 있도록") |
| `/wrapup check`(60분 전) → `/wrapup retro`(30분 전) → `/grill quiz` | `/wrapup` 한 번: check → retro → 퀴즈. 검증 실패가 남으면 멈춘다. 4시간이면 마무리 구간이 50분이라 "60분 전"이 시간표와 10분 어긋나던 문제도 사라졌다 |
| `/delegate`: 브리프 5줄을 보이고 "이대로 위임할까요?" | 두 줄만 보이고 바로 위임. 검증 명령·쓰기 범위가 비었거나 병렬 범위가 겹칠 때만 묻는다. 8절에서 남겼던 단계다. 지휘의 증거는 `/delegate Sn` 입력, 브리프 파일, 과잉 설계 고르기로 남는다 |

- 고르지 않은 것: 인터뷰 3회 고정(사용자는 반대로 길어질 수 있기를 원했다), `/kickoff`가 첫 질문 묶음까지 내기(효과가 작다).
- 효과(4시간, 슬라이스 5개 기준 추정): 명령·승인 입력이 약 26번에서 18번으로 준다. 명령은 6개에서 5개가 되고, 파일 수는 같다(`grill/SKILL.md` → `interview/grill.md`).
- 토큰: `/interview` 본문이 약 1,130에서 1,340토큰으로 늘었다(길이 조건과 다지기 안내). 마무리는 `/wrapup` 두 번과 `/grill` 한 번(약 3,150) 대신 `/wrapup` 한 번과 `grill.md`(약 2,300)를 읽는다. 합치면 비슷하다.
- 출력: CLAUDE.md의 끝 두 줄(`추가하지 않은 것:` / `확인하지 못한 것·리스크:`) 규칙을 "코드를 바꾼 답"으로 좁혔다. 시험에서 인터뷰 답에도 두 줄이 붙었고, 리허설 2의 인터뷰·`/spec` 기록에도 있던 현상이다.
- **확인.** 깨끗한 환경에서 헤드리스로 돌렸다(합계 약 $2.2).
  - 인터뷰(리허설 2 문서, 1단계 마감이 5분 지난 상태): 입력 형식을 바꿀 수 있는 답을 넣자 멈추지 않고 `보충 · 1단계 마감 +5분` 묶음을 냈다. SPEC과 어긋난 점은 추천을 붙여 사람에게 하나만 물었다. 그것이 풀리자 결정을 자동 기록(D-010)하고 "인터뷰를 마칩니다"와 함께 다지기 첫 질문을 냈다. 답 하나는 한 곳(D-011)에만 적혔다. "그만"에 남은 질문을 `→ 페르소나`로 넘기고, `다지기:` 줄을 남기고, 요약·퀴즈·채점까지 했다. 퀴즈는 파일을 바꾸지 않았다.
  - 새 세션의 `/interview`는 남아 있던 확인 대기 항목으로 보충을 한 번 더 냈고, 그것이 풀리자 "다지기도 이미 했으므로" 다지기 없이 `/spec`을 안내했다.
  - 고친 것: 첫 요약이 13문장이었다. "7문장 이내, 넘으면 덜 중요한 사실을 뺀다"로 바꾸자 `/wrapup`의 요약은 7문장이었다.
  - `/delegate S5`(테스트 1개짜리 슬라이스): 묻지 않고 루트에서 직접 처리하고 검증·회귀·정리·커밋까지 했다. `/wrapup` 한 번이 check(커밋) → RETRO(커밋) → 요약·퀴즈 → 채점 → "RETRO.md를 처음부터 끝까지 읽어보세요"로 끝났다.
- **확인하지 못한 것.** 서브에이전트로 넘기는 경로(이번 슬라이스는 작아서 루트에서 처리), 대화형 질문 도구 화면, Codex.
