# 당일 치트시트 (한 장, 인쇄용)

## 시작 10분
1. 하네스 설치: `unzip -n harness.zip` (프로젝트 루트) 또는 `scripts/install.sh <프로젝트>`
2. `claude` 실행 → `/kickoff` (총 시간이 6h가 아니면 `/kickoff 4h`)
3. "모르는 것" 표를 보고 → `/interview`

## 전체 흐름
```
/kickoff → /interview ×3~4 → /spec → /workspace → /delegate S0 → /verify S0
→ [ /delegate Sn → /verify Sn → /lean → /decide → 커밋 → /clear ] × P0 개수
→ 매 정시 /verify all → (마감 60분 전) /lean all → /wrapup check → (30분 전) /wrapup retro
```

## 인터뷰 사다리 (한 묶음 = 한 칸, 3~5 질문)
① 지금은 어떻게 하세요? 어디서 시간이 가나요? 무엇을 어디에 기록하세요?
② 가장 불편한 순간은? 실수가 나는 지점은? 왜 아직 해결이 안 됐나요?
③ 데이터는 어디서 어떤 형식으로? 몇 명이 동시에? 예외 상황은? 하면 안 되는 것은?
④ 무엇이 되면 "됐다"고 하시겠어요? 하나만 된다면 무엇?
⑤ "핵심 흐름을 A→B→C로 보고 D는 이번에 빼려는데 맞나요?"
- 금지: "할 일을 정리해 주세요", 기술 용어가 든 질문, 예/아니오 질문의 연속
- 답변은 `/interview digest <답변>`으로 소화한다. 답변을 복붙해 "만들어줘" 금지.

## 위임 전 4가지 확인
검증 명령이 있는가 · 쓰기 범위가 폴더로 적혔는가 · 계약 샘플 값이 그대로 들어 있는가 · 비목표가 적혀 있는가

## AI가 끼워 넣을 때 하는 말
"SPEC에 근거가 없다. 지금 규모에서는 불필요하다. 제거하고 단순한 버전으로." → `/decide`로 기록
자주 나오는 것: 설정 옵션, 구현 하나뿐인 추상 클래스, 재시도, 캐시, 락·큐, 범용 에러 래퍼, 로깅 프레임워크, 페이지네이션, "나중을 위한" 파라미터
자르면 안 되는 것: 입력 검증, 데이터 유실 방지, 보안, 접근성, 명시적으로 요구된 것

## 버그가 나면
재현 명령 먼저 → 원인·파일·검증 3줄 브리핑 → 최소 수정 → 재현 재실행. 에러 문구 복붙 반복 금지.

## 토큰
슬라이스가 끝나면 `/clear` (상태는 `docs/`에 있다) · 저장소 전체 스캔 금지, diff만 · 큰 구현은 서브에이전트로

## 마지막 60분
새 기능 금지 → `/lean all` → `/wrapup check` (README 3단계, 잔재 제거, 화면 직접 확인) → `/wrapup retro` → `RETRO.md`를 끝까지 읽기

## 하네스를 못 올릴 때: 손으로 치는 최소 CLAUDE.md
```
# 규칙
- 이 세션은 설계자. 구현은 슬라이스 단위로 서브에이전트에 위임. 결정은 한 번에 하나, 추천안과 함께 묻기.
- 상태는 docs/SPEC.md(목표·P0·비목표), docs/CONTRACT.md(인터페이스·샘플 값), docs/TASKS.md(슬라이스·검증 명령), docs/DECISIONS.md(결정·거절한 AI 제안)에 기록.
- SPEC에 없는 기능·옵션·추상화·재시도·캐시 금지. 뺀 것은 한 줄로 언급. 입력 검증·데이터 보호·보안은 자르지 않음.
- 수정 전 3줄 브리핑(원인/파일/검증). 버그는 재현부터. 저장소 전체 스캔 금지.
- 답변 끝 두 줄: "추가하지 않은 것:" / "확인하지 못한 것·리스크:"
```
