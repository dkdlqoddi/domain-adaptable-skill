# 당일 치트시트 (한 장, 인쇄용)

## 시작 10분
1. 하네스 설치: `unzip -n harness.zip` (프로젝트 루트) 또는 `scripts/install.sh <프로젝트>`
2. `claude` 실행 → `/kickoff 4h` (2차 예선 4시간: 탐색 ~0:40 → 계약·뼈대 ~1:20 → 구현 ~3:10 → 마무리 ~4:00. 생략하면 6h)
3. → `/interview`

## 전체 흐름 (명령 5개 + 선택 `/grill`)
```
/kickoff → /interview → (페르소나에게 묻기 → /interview <답>) ×3~4 → (선택) /grill → /spec → /delegate S0
→ [ /delegate Sn → /clear ] × 슬라이스 수 → (마감 60분 전) /wrapup check → (30분 전) /wrapup retro → (선택) /grill quiz
```
- `/grill`은 문서의 빈틈을 하나씩 추천 답과 함께 묻고(모르면 "페르소나에게") 기존 문서에 바로 적은 뒤 요약·퀴즈 4문항. 퀴즈는 복습용이라 커밋·푸시를 막지 않는다.
- `/delegate` 하나가 위임 → 검증·회귀 확인 → 과잉 설계 정리 → 커밋까지 한다.
- 결정은 명령이 `DECISIONS.md`에 자동 기록한다. 직접 남기려면 "이 결정 기록해 줘".

## 인터뷰 사다리 (한 묶음 = 한 칸, 3~5 질문)
① 지금은 어떻게 하세요? 어디서 시간이 가나요? 무엇을 어디에 기록하세요?
② 가장 불편한 순간은? 실수가 나는 지점은? 왜 아직 해결이 안 됐나요?
③ 데이터는 어디서 어떤 형식으로? 몇 명이 동시에? 예외 상황은? 하면 안 되는 것은?
④ 무엇이 되면 "됐다"고 하시겠어요? 하나만 된다면 무엇?
⑤ "핵심 흐름을 A→B→C로 보고 D는 이번에 빼려는데 맞나요?"
- 금지: "할 일을 정리해 주세요", 기술 용어가 든 질문, 예/아니오 질문의 연속
- 페르소나의 답은 통째로 `/interview <답>`에 붙인다. 정리하고 다음 질문까지 나온다. 답을 복붙해 "만들어줘" 금지.
- 샘플 데이터가 있으면 ③ 전에 훑는다. S2 무렵 실제 출력을 한 번 보여 준다. 둘 다 숨은 요구를 연다.

## 위임 전 4가지 확인
검증 명령이 있는가 · 쓰기 범위가 폴더로 적혔는가 · 계약 샘플 값이 그대로 들어 있는가 · 비목표가 적혀 있는가

## AI가 끼워 넣을 때 하는 말
"SPEC에 근거가 없다. 지금 규모에서는 불필요하다. 제거하고 단순한 버전으로." → `DECISIONS.md`에 자동 기록
자주 나오는 것: 설정 옵션, 구현 하나뿐인 추상 클래스, 재시도, 캐시, 락·큐, 범용 에러 래퍼, 로깅 프레임워크, 페이지네이션, "나중을 위한" 파라미터
자르면 안 되는 것: 입력 검증, 데이터 유실 방지, 보안, 접근성, 명시적으로 요구된 것

## 버그가 나면
재현 명령 먼저 → 원인·파일·검증 3줄 브리핑 → 최소 수정 → 재현 재실행. 에러 문구 복붙 반복 금지.

## 구현 중 새 요구가 나오면
`/interview <답>` → `/spec` 다시 (P0가 꽉 찼으면 P1부터, 입출력 샘플·픽스처 갱신, 슬라이스 추가) → `/delegate`

## 토큰
슬라이스가 끝나면 `/clear` (상태는 `docs/`에 있다) · 저장소 전체 스캔 금지, diff만 · 큰 구현은 서브에이전트로

## 마지막 60분
새 기능 금지 → `/wrapup check` (통합 검증, README 3단계, 잔재 제거, 화면 직접 확인) → `/wrapup retro` → `RETRO.md`를 끝까지 읽기 → (선택) `/grill quiz`

## Codex만 있을 때 (`claude` 명령이 없음)
`cp CLAUDE.md AGENTS.md && mkdir -p .agents && cp -r .claude/skills .agents/skills` → 명령 앞의 `/`를 `$`로 바꿔 부른다(`$kickoff`). 서브에이전트 위임이 안 되면 브리프대로 직접 구현한다.

## 하네스를 못 올릴 때: 손으로 치는 최소 CLAUDE.md (Codex면 같은 내용을 AGENTS.md로)
```
# 규칙
- 이 세션은 설계자. 구현은 슬라이스 단위로 서브에이전트에 위임. 결정은 한 번에 하나, 추천안과 함께 묻기.
- 상태는 docs/SPEC.md(목표·P0·비목표·입출력 샘플), docs/TASKS.md(슬라이스·검증 명령), docs/DECISIONS.md(결정·거절한 AI 제안, 생기면 바로)에 기록.
- SPEC에 없는 기능·옵션·추상화·재시도·캐시 금지. 뺀 것은 한 줄로 언급. 입력 검증·데이터 보호·보안은 자르지 않음.
- 수정 전 3줄 브리핑(원인/파일/검증). 버그는 재현부터. 저장소 전체 스캔 금지. 답은 짧게.
- 답변 끝 두 줄: "추가하지 않은 것:" / "확인하지 못한 것·리스크:"
```
