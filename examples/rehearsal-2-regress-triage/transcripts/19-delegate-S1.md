# 작업 브리프: S1 실패 찾기·묶기·보관 행 쓰기 (비교 없음)

**목표:** 로그를 실제로 읽습니다. 끊긴 로그와 실패 묶음을 게시용 글에 내고, 같은 묶음을 보관 TSV에 씁니다. 아직 비교가 없으므로 실패는 전부 `[새로 생긴 실패]`에 넣고, `[계속 남은 실패]`는 늘 `없음`이며, 첫 줄은 늘 `비교 기준: 없음`입니다.

**완료 기준**
1. TASKS.md의 S1 검증 명령(unittest, 10-24 출력 diff, 10-24 TSV diff)이 통과해야 합니다.
2. **추가한 확인:** 빈 보관 폴더로 `samples/2026-10-25`를 실행합니다.
   - 표준출력은 브리프의 "기대 출력 2"와 글자 단위로 같아야 합니다. 끊긴 로그 `axi_stress, seed 2개 중 1개(55)`가 나오고, `dma_burst … 2개 중 2개(202, 203)`를 포함한 실패 3줄이 전부 새로 생긴 실패로 나와야 합니다.
   - TSV는 `fixtures/expected/2026-10-25.tsv`와 diff 0이어야 합니다.
   - 이유: 10-24에는 끊긴 로그도, 두 seed 묶음도 없습니다. TASKS.md 검증 명령만으로는 F1·F2의 핵심을 확인할 수 없습니다.
3. `LANG=C LC_ALL=C`로 실행해도 같은 글이 나와야 합니다.

**범위**
- 쓰기: `regsum.py`, `test_regsum.py`(새 파일), TASKS.md의 S1 행
- 읽기만: samples 두 밤, `fixtures/keys.tsv`, 관련 expected·history 파일
- `check.sh`는 수정 금지

**계약 (값을 그대로 복사해 넣음)**
- 함수 경계: CONTRACT A 표의 `is_error_line`, `is_truncated`, `failure_key`, 그리고 keys.tsv의 3개 샘플. 16진수를 먼저 지운다는 주의도 넣었습니다.
- 로그 읽기 규칙:
  - 폴더 바로 아래 `*.log`만 읽습니다.
  - 파일 이름 정규식으로 테스트와 seed를 뽑고, 전체 seed 수는 로그 파일 수로 셉니다.
  - 로그는 `errors="replace"`로 읽습니다.
- 분류 순서:
  1. 끊긴 로그 → 끊긴 로그로만 셉니다. 에러 줄이 있으면 `: 원문`을 붙이고, 묶음과 보관에는 넣지 않습니다.
  2. 그다음 에러 줄이 있으면 실패입니다.
  3. 나머지는 통과입니다.
- 함정: `UVM_ERROR :    0` 같은 요약 줄과 `UVM_WARNING` 줄은 에러 줄이 아닙니다.
- 묶기: (테스트, 묶음 기준 줄)이 같으면 한 묶음이고, 원문은 가장 작은 seed의 첫 에러 줄을 씁니다.
- 출력·TSV 모양: CONTRACT C·D 규칙과 기대 출력 1·2, 보관 TSV 샘플 2개(탭 표기)를 넣었습니다.

**하지 말 것**
- S2(비교 기준과 칸 나누기)와 S3(종료코드 2, 경고, 임시 파일) 기능은 만들지 않습니다.
  - 이름 모양이 다른 `.log`는 조용히 건너뛰고 `shortcut:` 주석만 남깁니다.
  - S2가 칸 나누기를 끼워 넣기 쉽게 묶기 함수와 출력 함수는 분리해 둡니다. 클래스는 쓰지 않습니다.
- SPEC 비목표 전체, Python 3.7+ 기능, argparse·logging·새 패키지는 쓰지 않습니다.
- 테스트는 작게 둡니다: keys.tsv 기반 `failure_key`, `is_error_line`(에러 줄 / 요약 줄 / WARNING), `is_truncated`(요약 / `$finish`만 / 둘 다 없음), `unittest`만.
