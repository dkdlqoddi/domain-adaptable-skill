## 모르는 것
| 범주 | 모르는 것 | 모른 채 만들면 생기는 위험 |
|---|---|---|
| 사용자 | 정리하는 사람(담당자 1명인지, 당번제인지)과 결과를 받아 보는 사람(팀원, 리드)이 각각 무엇을 보고 싶어 하는가 | 정리하는 사람만 편해지고, 받아 보는 사람에게 필요한 정보(이 실패를 누가 봐야 하는지 등)가 빠진다 |
| 지금 일하는 방식 | 지금 정리 절차의 단계와 가장 오래 걸리는 단계(취합, 실패 분류, 원인 추적, 작성 중 어디?) | 시간이 안 드는 단계를 자동화하고 진짜 병목은 그대로 남는다 |
| 데이터(형식·규모) | 결과 형식, 하룻밤에 도는 테스트 수, 두 밤을 비교하는 의미(새 실패, 고쳐진 것, 불안정한 테스트?) | 샘플에만 맞는 파서가 실제 데이터에서 깨지거나, 전날과 비교한다는 핵심을 놓친다 |
| 실행 환경 | 어디서 실행하는가(사내 리눅스 서버, LSF 같은 작업 스케줄러, 개인 PC), 설치할 수 있는 런타임, 외부 네트워크를 쓸 수 있는지 | 사내망에서 돌릴 수 없는 도구를 만든다 |
| 성공 기준 | 지금 정리에 몇 분 걸리고 목표는 몇 분인가, 공유 형태는 무엇인가(메일, 위키, 슬랙, 엑셀) | 완료 판단 기준이 없어 끝없이 다듬거나, 공유 채널에 붙여 넣을 수 없는 형식으로 출력한다 |
| 범위의 경계 | 원인 분석, 담당자 자동 배정, 대시보드, 자동 발송까지 하는가, 아니면 요약 초안까지만 하는가 | 범위가 부풀어 P0을 끝내지 못하거나, 꼭 필요한 한 단계를 빠뜨린다 |
