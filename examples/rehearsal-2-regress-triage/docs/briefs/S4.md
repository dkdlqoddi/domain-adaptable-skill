# 작업 브리프: S4 나눠 올리기 (F7, P1)

## 목표 (1문장)
게시용 글이 4000바이트(UTF-8)를 넘는 날에만 묶음 줄 경계에서 메시지 N개로 나눠 표준출력에 낸다. 넘지 않는 날의 출력과 보관 파일은 지금과 바이트 단위로 같다.

## 완료 기준
- [ ] `python3 -m unittest -q test_regsum` 통과
- [ ] `bash fixtures/check.sh` → ①②③④-a④-b⑤ 모두 PASS
- [ ] `LANG=C LC_ALL=C bash fixtures/check.sh`에서도 같은 결과
- [ ] `python3 regsum.py fixtures/split_logs/2026-10-26 <history_split 사본>` 출력을 구분 줄로 나눴을 때 메시지마다 (각 줄 + `\n`)의 UTF-8 바이트 합이 4000 이하 (실측 숫자를 보고에. 기대값은 3853, 829 근처)

## 지켜야 할 계약 (CONTRACT C "나눠 올리기", 그대로)
- 위 글 전체가 **4000바이트(UTF-8, 끝 줄바꿈 포함) 이하면 그대로** 낸다. ①~③ 기대 출력은 모두 이 경우다.
- 메시지 하나 = 첫 줄, 빈 줄, 칸들(칸 사이 빈 줄 하나). 메시지마다 (각 줄 + `\n`)의 UTF-8 바이트 합이 4000 이하.
- 첫 줄: 1번째는 원래 첫 줄 끝에 ` [1/N]`, 2번째부터는 `회귀 <회귀 날짜> 정리 [k/N]`.
- 칸 줄(묶음 줄·`없음`)을 순서대로 넣다가 다음 줄이 한도를 넘기면 새 메시지를 시작한다(앞에서부터 꽉 채움). 줄 중간은 자르지 않는다.
- 칸 제목은 그 칸의 첫 줄과 같은 메시지에 둔다(제목만 남기지 않음). 앞 메시지에서 이어지는 칸은 새 메시지에서 제목 뒤에 ` (이어서)`를 붙여 다시 쓴다.
- 메시지 사이: 빈 줄, `---------- 여기서 나눠 올림 ----------`, 빈 줄. 구분 줄은 메시지에 들지 않는다.
- N은 `[k/N]`을 포함해 나눈 결과의 개수(자릿수가 바뀌면 다시 나눈다).
- 보관 파일은 나누지 않는다. 종료코드 0.
- 처리하지 않음: 묶음 줄 하나가 혼자 한도를 넘는 경우 → 자르지 않고 그 메시지만 넘긴다. 이때 **무한 반복하지 않아야** 한다(빈 메시지를 만들지 말 것).

기대 출력 `fixtures/expected/2026-10-26_split.txt` 모양(줄임 — 원본은 직접 diff):
```
회귀 2026-10-26 정리 (비교 기준: 2026-10-25 결과) [1/2]

[끊긴 로그 — LSF 시간 제한, 또는 아직 실행 중]
- pcie_l1ss, seed 1개 중 1개(31)

[새로 생긴 실패]
- apb_reg, seed 2개 중 1개(3): UVM_ERROR tb/env/apb_reg_chk.sv(88) @ 41200: ...
  (… 21줄 …)
- spi_loop, seed 2개 중 1개(24): UVM_ERROR tb/env/spi_chk.sv(66) @ 404000: ...

---------- 여기서 나눠 올림 ----------

회귀 2026-10-26 정리 [2/2]

[새로 생긴 실패] (이어서)
- timer_wdt, seed 1개 중 1개(25): UVM_FATAL tb/env/wdt_mon.sv(40) @ 15000000: ...

[계속 남은 실패]
- ddr_init, seed 1개 중 1개(12): ...
- sec_aes, ...
- usb_enum, seed 1개 중 2개에서 1개로(26): ...
```
파일은 끝 줄바꿈 1개로 끝난다(지금 `render`와 같음).

## 현재 코드 상태 (참고)
- `render()`가 첫 줄과 세 칸(`section(title, lines)`)을 `"\n".join`으로 붙여 문자열을 돌려준다. 나누려면 (제목, 줄 목록) 구조가 필요하다. 어떻게 나눌지는 맡기되, 4000 이하 경로의 출력이 바뀌면 안 된다(①~③이 지킨다).
- `main()`은 마지막에 `sys.stdout.buffer.write(...encode("utf-8"))`로 낸다. 이 방식을 유지한다.

## 하지 말 것
- SPEC 비목표: 나눠 올리기의 한도 지정 옵션, 메시지별 파일 따로 쓰기, 메신저 자동 분할 게시(F7은 표준출력에 구분 줄만), 묶음 줄 하나가 혼자 4000을 넘는 경우의 처리. 설정 파일, 옵션 플래그, 외부 패키지, Python 3.7+ 전용 기능.
- 한도는 모듈 상수 하나(`4000`). CLI 인자·환경 변수·설정으로 바꿀 수 있게 하지 않는다. 클래스, argparse, logging을 들이지 않는다.
- 보관 파일 쓰기, 오류 경로, 비교 로직은 손대지 않는다.
- 계약을 바꾸지 않는다. 막히면 `docs/TASKS.md` BLOCKER 표에 적고 멈춘다.
- 테스트는 `unittest`로 작게, 나누는 함수만(2~3개): ① 4000 이하면 나누지 않음 ② 넘으면 메시지마다 4000 이하, 이어지는 칸에 ` (이어서)`, 제목만 남은 메시지 없음 ③ (선택) 한 줄이 혼자 4000을 넘어도 끝남. 긴 줄을 만들어 실제 4000 상수로 시험한다. 테스트 때문에 한도 인자를 추가하지 않는다.
