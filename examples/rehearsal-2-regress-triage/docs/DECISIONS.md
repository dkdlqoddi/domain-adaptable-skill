## D-001 "실패 로그"의 정의 (2026-10-26, 인터뷰 3회차 직전)
- 상황: 모든 로그 끝 요약에 `UVM_ERROR :    0`이 있어, 담당자의 원래 정의("`UVM_ERROR`/`UVM_FATAL`이 들어 있는 로그")로는 통과 로그까지 걸린다
- 선택: 끝 요약 줄을 뺀 실제 에러 줄이 하나라도 있는 로그 = 실패 로그. 끊긴 로그는 따로 실패로 센다(인터뷰 3회차)
- 대안과 기각 이유: 단어 포함(통과 로그까지 실패), `TEST FAILED` 줄(테스트마다 있고 없음), 요약 집계 숫자(어차피 첫 에러 줄을 읽어야 하고 끊긴 로그엔 요약이 없음)
- AI 제안 여부: AI가 추천 → 사람이 동의

## D-002 "같은 실패" 기준 (2026-10-26, 인터뷰 4회차 정리)
- 상황: 담당자 기준(3회차 "첫 에러 줄에서 숫자를 뺀 같은 줄이면 같은 실패")과 2회차 DMA 기록("숫자만 지우고 비교하면 놓칠 수 있다")이 충돌해 보였다
- 선택: 담당자 기준을 따른다. DMA 착각의 원인은 숫자 무시가 아니라 파일 이름·태그만 보고 뒤쪽 메시지를 안 본 것 → 기록을 "파일 이름과 태그만 보고 비교하면 놓친다"로 고침
- 대안과 기각 이유: 숫자까지 같아야 같은 실패(uart_loop lane 0/1, dma_burst s202/s203처럼 같은 원인이 매일 "새 실패"로 떠서 담당자 방식과 어긋남), 파일 이름+태그(DMA 착각을 그대로 재현)
- 미룬 것: 소스 줄 번호(`dma_scoreboard.sv(142)`)를 비교에 남길지는 `/spec`에서
- AI 제안 여부: AI가 추천 → 사람이 동의

## D-003 지난 결과 보관과 비교 기준 (2026-10-26, 인터뷰 4회차 정리)
- 상황: "새 실패"를 가리려면 지난 회귀 결과가 있어야 하는데, 이를 어디에 어떻게 보관하고 어느 날짜와 비교할지 정해야 했다
- 선택: 도구가 돌 때마다 출력한 결과를 회귀 날짜별 텍스트 파일로 남기고, 오늘보다 앞선 회귀 날짜 중 가장 최근 결과와 비교한다. 같은 날짜로 다시 돌리면 덮어쓰고, 출력 첫 줄에 비교 기준 날짜를 보여 준다
- 대안과 기각 이유: 채널에 올린 글을 붙여 넣어 비교(매일 단계가 하나 늘고, 사람이 고친 글을 읽어 내는 방식은 깨지기 쉬움)
- AI 제안 여부: AI가 추천(인터뷰 4회차) → 사람이 그대로 수용

## D-004 묶음 기준 줄의 세부 규칙 (2026-10-26, /spec)
- 상황: D-002가 미룬 소스 줄 번호, 그리고 "숫자"에 16진수가 드는지, 다른 테스트끼리 묶는지가 남아 있었다
- 선택: 16진수(`0x…`)를 먼저, 이어서 10진수를 모두 `#`로 바꾼다(소스 줄 번호·시뮬 시간 포함). 묶음은 테스트 이름 + 묶음 기준 줄 단위(다른 테스트는 따로)
- 대안과 기각 이유: 10진수만 지움(`0x0badf00d`→`0xbadfd`가 남아 dma_burst s202·s203이 갈라짐), 줄 번호 유지(담당자 기준 "숫자를 뺀 같은 줄"과 다르고, 코드 수정만으로 매일 새 실패가 뜸), 다른 테스트끼리 묶기(게시 예시가 테스트 단위, 덜 묶는 쪽이 안전)
- AI 제안 여부: AI가 결정(근거: 인터뷰 3회차 기준, success.md "덜 묶는 쪽") → 사람 확인 대기

## D-005 보관 파일 형식 (2026-10-26, /spec)
- 상황: D-003은 "출력한 결과를 텍스트 파일로" 남기기로 했는데, 게시 글을 다음 날 다시 읽어 내려면 묶음 기준 줄과 seed 수를 글에서 역으로 뽑아야 한다
- 선택: 게시 글과 같은 묶음 목록을 TSV(`test⇥total⇥seeds⇥key`)로 따로 남긴다. 끊긴 로그는 비교하지 않으므로 넣지 않는다. 형식이 깨졌으면 종료코드 2로 멈춘다
- 대안과 기각 이유: 게시 글 원문 저장 후 파싱(`1개에서 2개로` 같은 표현 때문에 깨지기 쉬움), JSON(사람이 grep·awk로 보기 불편, 이득 없음), 깨진 파일 무시(모든 묶음이 "새로 생김"으로 잘못 뜸)
- AI 제안 여부: AI가 결정 → 사람 확인 대기

## D-007 F7 나눠 올리기의 우선순위와 끊는 위치 (2026-10-26, /spec)
- 상황: 5회차 "원인 많은 날 4000자를 넘겨 나눠 올려야 한다"와 6회차 "넘겨 본 기억이 거의 없다"가 어긋났다. 사람이 추천대로 (나)로 판단 = 6회차를 최신 사실로 보고 "드물지만, 넘는 날엔 메신저가 막는다"로 읽는다. 끊는 위치는 담당자 방식이 없어 만드는 쪽이 정한다
- 선택: F7 = P1(S3 다음). 4000을 **UTF-8 바이트**로 세어 넘을 때만 나누고, 묶음 줄 경계에서 앞 메시지를 꽉 채워 끊는다. 이어지는 칸은 제목에 `(이어서)`를 붙여 다시 쓰고, 첫 줄에 `[k/N]`, 메시지 사이에 구분 줄. 보관 파일은 나누지 않는다 (CONTRACT v2)
- 대안과 기각 이유: P0(P0 3개 상한, 드물고 줄 단위라 손으로 나눌 수 있음), P2(넘는 날엔 아예 안 올라가고 success.md에 명시), 칸 경계에서만 끊기(새로 생긴 실패 칸 하나가 4000을 넘으면 결국 줄에서 끊어야 함), 글자 수로 세기(메신저가 바이트로 세면 한글 칸 제목 때문에 넘을 수 있음), 칸 제목 반복 없음(둘째 메시지의 새로 생긴 실패를 계속 남은 실패로 읽을 위험 = 1순위 위험), 메시지별 파일·옵션(비목표: 옵션 플래그)
- AI 제안 여부: 사람이 "우선순위와 끊는 위치를 정하라"고 위임 → AI가 결정, 사람 확인 대기(모양은 다음 인터뷰에서 담당자 확인, SPEC 7)

## D-008 오류 경로의 빈칸 해석 (2026-10-26, /delegate S3)
- 상황: CONTRACT C 오류 표의 "보관 파일 안 씀"이 보관 폴더 생성까지 막는지, `<N>번째 줄`을 어떻게 세는지, 폴더 이름·`.log` 0개를 무엇으로 판단하는지 적혀 있지 않았다
- 선택: 오류 경로에서는 보관 폴더도 만들지 않는다(검사를 표 순서대로 모두 끝낸 뒤 `makedirs`). `N` = 머리 줄을 1로 센 파일 줄 번호, 빈 줄도 깨짐. 폴더 이름은 `^\d{4}-\d{2}-\d{2}$`만 본다(달력 검사 없음). `.log` 0개는 이름 모양과 무관하게 `*.log` 개수. 보관 파일 쓰기 = `<날짜>.tsv.tmp` → `os.replace`
- 대안과 기각 이유: 보관 폴더는 먼저 만들기(실패한 실행이 빈 폴더를 남겨 대리자가 헷갈림, 검증 ④-a가 빈 폴더 요구), 데이터 줄만 세기(파일을 열었을 때 보이는 줄 번호와 달라짐), 달력 검사(`2026-02-30` 같은 이름은 사람이 만들지 않음, 코드만 늘어남), `tempfile.mkstemp`(실행자 1명이라 고정 이름으로 충분)
- AI 제안 여부: AI 추천 → 사람이 "오류 시 보관 폴더 안 만듦"을 추천대로 승인, 나머지는 가정으로 브리프에 명시
