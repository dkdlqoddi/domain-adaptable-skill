## 아직 모르는 것
> ①~⑤ 채워짐(⑤ 4회차 확인, 5회차에 실제 출력으로 재확인, 6회차에 메시지 한도 확인). 아래는 인터뷰 대신 `/spec`에서 가정·결정으로 처리한다.
- ~~4000자를 넘는 날 어디서 끊나~~ → `/spec`에서 결정(D-007): 줄 경계, 앞에서부터 꽉 채움, 이어지는 칸은 제목 `(이어서)`. 담당자에게 남은 확인 = 그 모양으로 나눠 붙이기 편한가(SPEC 7)
- (5회차, 담당자 확인 대기) 실제 회귀 폴더에서 seed 수가 `5개 중 n개`로 나오는지. 도구는 폴더 안 로그 파일 수를 세므로 맞게 나와야 함(루트에서 5개짜리 폴더로 확인)
- 지난 결과 보관 방식(도구가 남긴 결과 vs 게시 글 붙여 넣기)과 위치 — **루트 판단 대기**. 담당자는 게시 전에 글을 손보는지 미확인
- 8시에 아직 도는 실행: 드물지만 있을 수 있음. 끊긴 로그와 같이 맨 위에 올리되 "아직 도는 중일 수 있음"을 붙일지 (`/spec`)
- 에러 줄이 있는데 끝(요약·`$finish`)도 없는 로그는 끊긴 로그로 맨 위에 올리나 (`/spec`, 덜 묶는 쪽 = 맨 위 추천)
- 다른 테스트끼리 같은 줄이면 한 묶음인가 (`/spec`, 게시 예시가 테스트 단위라 테스트별로 묶기 추천)
- 소스 줄 번호를 비교에 남기나 (`/spec`, D-002에서 미룸)
- 첫 실행 날에는 비교할 도구 결과가 없다(지금 게시 글은 실패 실행당 한 줄 모양) (`/spec`)
- (가정으로 처리, 묻지 않음) `UVM_ERROR`/`UVM_FATAL`은 구분하지 않고 첫 에러 줄을 그대로 보여 준다. 줄에 등급이 그대로 보인다
- (가정으로 처리) 휴가 중 동료가 올린 글이 있으면 그 글이 "마지막 게시 글"이다. 누가 올렸든 채널에 마지막으로 올라간 정리 글이 기준
