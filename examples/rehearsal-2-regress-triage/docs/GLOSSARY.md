# GLOSSARY — 도메인 용어집

> 인터뷰에서 **확정된** 용어만 한 줄씩. 구현 세부사항은 쓰지 않는다. 코드·파일·API 이름은 이 용어를 따른다.
> 한 단어가 두 뜻으로 쓰이면 두 용어로 나눈다.

| 용어 | 뜻 (현업의 말로) | 유사어·주의 |
|---|---|---|
| 실패 로그 | 끝 요약 줄(`UVM_ERROR :    0` 같은 집계)을 뺀 **실제 에러 줄**(`UVM_ERROR`/`UVM_FATAL`로 시작)이 하나라도 있는 로그 (D-001) | 단어만 grep하면 모든 로그가 걸린다. 끊긴 로그는 여기 안 들어가지만 실패다 → "실패 실행" 참고 |
| 끊긴 로그 | 끝에 `UVM Report Summary`도 `$finish`도 없이 중간에 끝난 로그. LSF 시간 제한(4시간)에 걸려 죽은 것. 에러 줄이 없어도 **실패**. 설계가 멈췄을 수 있어 가장 먼저 본다 (3회차) | pcie_link의 `[LINK] timeout ...`(시뮬레이션 안의 타임아웃, 에러 줄 있음)과 다르다. 코드에서 둘을 "timeout" 한 단어로 부르지 않는다 |
| 첫 에러 줄 | 실패 로그에서 처음 나오는 에러 줄. 실패를 대표하는 정보로 쓴다 | |
| seed | 테스트 실행에 쓴 랜덤 seed. 테스트 이름과 함께 실패 실행 하나를 식별한다. 로그 파일 이름 `__s<seed>`에서 읽는다 | |
| 테스트 이름 | 로그 파일 이름의 `__s` 앞부분(예: `dma_burst`) | 로그 안 `Run:` 줄에는 `dma_burst_test`처럼 `_test`가 붙는다. 파일 이름 쪽을 쓴다 |
| 실패 실행 | 테스트 이름 + seed 한 건이 실패한 것(실패 로그 또는 끊긴 로그). 로그 파일 하나 | "실패"를 그냥 쓰지 않는다. 묶음과 구분 |
| 실패 묶음 | 같은 원인으로 보는 실패 실행들의 모임. 게시할 때 한 줄로 쓴다. 담당자 기준: 첫 에러 줄에서 숫자를 빼고 같은 줄이면 같은 묶음(uart_loop lane 1·lane 0도 같은 묶음) (3회차) | 파일 이름과 태그만 같다고 같은 묶음이 아니다(DMA 사례, D-002). 다른 테스트끼리도 한 묶음이 되는지는 미확인 |
| 새로 생긴 실패 | 지난 게시 글에 없던 **실패 묶음**. 설계팀에 알리고 끊긴 로그 다음에 올린다 (3·4회차) | "알려진 실패"(위키 표)와 다른 뜻. 있던 묶음이 새 seed에서 나는 것은 여기 아님 |
| 계속 남은 실패 | 지난 게시 글에도 있던 **실패 묶음**. seed가 늘었어도 여기에 넣고 `5개 중 2개에서 4개로`처럼 변화를 보인다 (4회차) | |
| 지난 게시 글 | 담당자가 마지막으로 채널에 올린 정리 글. 비교 기준. 월요일이면 보통 금요일 글 (3회차) | "어제 결과"라고 쓰지 않는다. 그 사이 밤들의 실패는 이 글에 없다 |
| 알려진 실패 (위키) | 팀 위키의 "알려진 실패" 표. 사람이 가끔 고쳐 신뢰도가 낮다 | "어제도 있던 실패"와 혼동 주의 → 코드에서는 다른 이름으로 |
| 회귀 날짜 | 회귀를 시작한 밤의 날짜. 로그 폴더 `/proj/soc/regress/<날짜>/`의 이름 | 아침 정리하는 날보다 하루 앞. "오늘 날짜"와 혼동 주의 |
| 태그 | 에러 줄 안의 `[SCB]` 같은 대괄호 표시 | 태그가 같아도 원인이 다를 수 있다(DMA 사례). 태그 종류·뜻은 미확인 |
| 묶음 기준 줄 | 첫 에러 줄에서 숫자(16진 `0x…`, 10진, 소스 줄 번호·시뮬 시간 포함)를 `#`로 바꾼 줄. 같은 테스트에서 이 줄이 같으면 같은 실패 묶음 (D-002, D-004) | 코드 이름 `failure_key`. 태그만 같은 것과 다르다 |
| 보관 파일 | 도구가 실행마다 회귀 날짜별로 남기는 실패 묶음 목록(`<YYYY-MM-DD>.tsv`). 다음 실행의 비교 기준이 된다 (D-003, D-005) | 코드 이름 `history`. 위키 "알려진 실패"와 다르다 |
| 비교 기준 | 이번 회귀 날짜보다 앞선 보관 파일 중 가장 최근 것. "지난 게시 글"을 도구 안에서 대신한다 (D-003) | 출력 첫 줄에 날짜를 보인다 |
| 메시지 한도 | 메신저 한 메시지에 올라가는 최대 길이 4000자. 넘으면 메신저가 막는다 (5·6회차) | 코드에서는 UTF-8 바이트로 센다(D-007). "읽기 편한 길이" 같은 다른 기준은 없다 |
| 나눠 올리기 | 게시용 글이 메시지 한도를 넘는 날 묶음 줄 경계에서 메시지 여러 개로 나누는 것 (D-007) | 넘지 않는 날은 나누지 않는다. 보관 파일은 나누지 않는다 |
