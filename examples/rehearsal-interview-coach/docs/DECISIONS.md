## D-001 코칭 기록 저장소는 로컬 JSON 파일 1개
- 상황: 코칭 기록을 어디에, 어떤 형태로 저장할지 (SPEC 5. 제약의 데이터 규모·동시 쓰기 항목은 아직 비어 있음)
- 선택: 로컬 JSON 파일 1개. 동시 사용자가 없고 데이터가 수백 건 규모라서
- 대안과 기각 이유: (추정) SQLite — 동시 쓰기가 없어 잠금·트랜잭션이 필요 없고 스키마·설정 비용만 남는다 / DB 서버(Postgres 등) — 수백 건에 과하고 실행 환경에 서버가 없다
- AI 제안 여부: 없음 (추정) — 이 세션에서 AI 제안 없이 사람이 직접 정함

## D-002 실행 형태: Python 표준 라이브러리 서버 + 정적 HTML (가정)
- 상황: 코치가 노트북에서 어떻게 실행하고, 화면과 저장을 무엇으로 만들지 (SPEC 5: 노트북 1대, 외부 전송 금지, D-001 JSON 파일)
- 선택: `api/` = Python 3 표준 라이브러리(`http.server`, `json`)만 쓰는 로컬 서버, `ui/` = 빌드 없는 HTML/JS 한 장. 실행은 `python3 api/server.py` 한 줄. (가정 A9: 노트북에 Python 3.10+가 있다)
- 대안과 기각 이유: 정적 HTML + localStorage — 설치가 전혀 없지만 D-001(JSON 파일 1개)을 지키지 못하고 브라우저 데이터 삭제 시 시즌 기록이 사라지며 명령으로 검증하기 어렵다 / Node + React 등 프레임워크 — 패키지 설치·빌드가 생기고 화면 하나·엔드포인트 셋에 과하다 / CLI만 — "하나만 된다면 비교 화면"이라 화면이 필수
- AI 제안 여부: 리허설 모드에서 AI(루트)가 셋을 비교해 추천 → 사람 확인 없이 수용(가정). Python이 없는 노트북이면 A9가 깨진다 — 실행 파일 묶음 또는 정적 HTML 전환 검토

## D-003 코드 이름은 GLOSSARY "코드 표기" 열을 따른다 (가정)
- 상황: JSON 키·변수·경로 이름을 한글 용어 그대로 쓸지, 영문으로 쓸지 (CLAUDE.md "코드 이름은 이 용어를 따른다")
- 선택: GLOSSARY에 "코드 표기" 열을 추가하고 코드에는 그 영문 표기만 쓴다(`player`, `date`, `items.key_message`…). 표에 없는 이름은 코드에 못 쓴다 — 새 이름이 필요하면 GLOSSARY부터 고친다. 상·중·하 값만은 한글 그대로 저장한다
- 대안과 기각 이유: 한글 키(`"선수"`) — 뜻은 가장 가깝지만 URL 쿼리·셸·curl 검증에서 인코딩이 번거롭고 파일명에 못 쓴다 / 자유 영문 — `session`, `score`, `rubric` 같은 현업에 없는 개념이 스며들어 용어가 표류한다
- AI 제안 여부: AI가 제안 → 수용(가정)

## D-004 같은 선수·같은 날짜 재저장은 덮어쓰기 (가정)
- 상황: 기록의 저장 단위와, 이미 있는 `(선수, 날짜)`를 다시 저장할 때의 동작 (수정 기능이 SPEC에 없음)
- 선택: 기록 = 선수 × 연습 날짜 1건(가정 A1: 평가는 연습마다 한 번). `PUT /api/records`는 같은 키가 있으면 덮어쓰고 `replaced:true`를 돌려준다. 화면은 선택한 날짜의 기록이 있으면 그 값을 입력란에 먼저 채워 코치가 보고 고치게 한다 — 이것이 수정 기능이며, 모르고 덮어쓰는 일을 막는다
- 대안과 기각 이유: 409 충돌 + "덮어쓸까요?" 확인 — 분기와 화면 상태가 하나 더 늘고, 사전 채움이 같은 목적을 더 단순하게 이룬다 / 이력 보존(버전 배열) — SPEC에 없고 비교 화면에 쓰이지 않는다
- AI 제안 여부: AI가 이력 보존을 언급 → 거절(비목표 "수정 이력"). 덮어쓰기 + 사전 채움은 수용(가정)

## D-005 선수는 이름 문자열로 식별 (가정)
- 상황: 선수를 id로 관리할지 이름으로 식별할지 (선수 명단이 따로 없음)
- 선택: 이름 문자열(앞뒤 공백 제거) 그대로 키. 선수는 기록에 처음 적힐 때 생긴다. 화면은 기존 이름 목록에서 고르게 해 오타를 줄인다. `shortcut: 동명이인·오타는 다른 선수가 된다, 동명이인이 생기면 등번호 등 구분자를 붙이는 쪽으로 바꾼다`
- 대안과 기각 이유: id 발급 + 선수 관리 화면 — 화면·API가 하나씩 늘고 SPEC에 없다. 한 팀 3~4명 규모에서 이름 충돌은 드물다
- AI 제안 여부: AI가 id 발급 제안 → 축소(이름 키 + 목록 선택)(가정)

## D-006 메모는 P1이지만 스키마에는 v1부터 (가정)
- 상황: 메모(F3)는 비교 화면보다 뒤(P1)인데 기록 스키마에 지금 넣을지
- 선택: `memo` 필드를 v1 스키마에 넣고(빈 문자열 허용) 화면 노출만 P1로 미룬다. 필드 하나라 지금 넣는 비용이 0이고, 나중에 넣으면 파일·픽스처·검증을 다시 고친다
- 대안과 기각 이유: P1 때 추가 — 계약 v3와 픽스처 재작업이 생긴다 / 답변 텍스트·코치·질문도 같이 미리 넣기 — 필요 여부가 미확인이라 선점하지 않는다(비목표)
- AI 제안 여부: AI가 "나중에 쓸 필드를 미리 다 넣자" 제안 → 축소(메모만)(가정)

## D-007 ui의 Mock = S0 뼈대 서버의 스텁 응답 (가정)
- 상황: ui는 api 코드를 열지 않고 `fixtures/*.response.json`으로 먼저 만들어야 한다(아키타입 D). 브라우저는 `file://`에서 fetch를 못 하므로 무언가가 응답을 줘야 한다 (`/workspace`)
- 선택: S0 뼈대 서버가 `GET /api/compare`·`PUT /api/records`를 픽스처 내용으로 응답한다(`# S0 stub`, 선수 이름으로 픽스처를 고르고 그 외는 빈 응답). ui는 같은 실행 명령(`UP`)으로 Mock을 얻고, S1·S3이 스텁을 실제 로직으로 바꾸면 같은 명령이 실제 응답이 된다. 추가 파일·분기 없음
- 대안과 기각 이유: ui JS에 `?mock=1` 분기 — 제품 코드에 개발용 분기가 남는다 / `fixtures/mock/` 트리 + `python3 -m http.server` — 심링크·중복 파일이 생기고 PUT은 501 / ui를 api 뒤에 순차로 — 병렬성을 잃는다(2h45m에 슬라이스 5개)
- AI 제안 여부: AI(루트)가 셋을 비교해 추천 → 사람 확인 없이 수용(가정)

## D-008 ui 검증은 브라우저 시나리오, 자동화 도구는 추가하지 않는다 (가정)
- 상황: ui 슬라이스의 검증 명령을 무엇으로 할지. api는 unittest지만 화면은 명령 한 줄로 검증되지 않는다 (`/workspace`)
- 선택: SPEC F2·F1 완료 기준을 브라우저 시나리오로 TASKS에 적고, 통합 체크포인트에서 루트가 세션의 Playwright 도구로 실제 서버에 같은 시나리오를 돌린다. 저장소에는 아무것도 추가하지 않는다
- 대안과 기각 이유: Playwright/Selenium 테스트 스크립트 — npm·pip 의존성과 브라우저 설치가 생긴다(비목표 "새 패키지") / 화면을 서버 사이드 렌더로 바꿔 curl로 검증 — "저장하면 바로 반영" 흐름이 나빠진다
- AI 제안 여부: AI가 Playwright 테스트 추가를 떠올림 → 거절(가정). 리스크: 마지막엔 사람이 눈으로 보는 단계가 남는다(`/verify ui`)

## D-009 S0 서버는 `ThreadingHTTPServer`, 파일 락은 두지 않는다 (가정)
- 상황: S0 뼈대 서버의 서버 클래스. 단일 스레드 `HTTPServer`는 브라우저가 미리 열어 두는 빈 연결(preconnect)에 묶여 다음 요청이 멈출 수 있다 (`/delegate S0` 서브에이전트 보고)
- 선택: 표준 라이브러리 `ThreadingHTTPServer`(`python -m http.server`와 같은 방식). 동시 사용자 1명(SPEC 5절)이라 S3의 읽기-수정-쓰기에 락·큐는 넣지 않는다 — 임시 파일→`os.replace`로 파일 자체는 항상 온전하다
- 대안과 기각 이유: `HTTPServer` 단일 스레드 — 브라우저 빈 연결에 묶이는 문제 / 락 추가 — 동시 쓰기가 없는데 코드만 는다(비목표 "동시 쓰기")
- AI 제안 여부: 서브에이전트가 Threading을 택하고 보고 → 루트 수용(가정). S3 브리프에 "락 없음, D-009"를 명시한다

## D-010 S0 lean 검토: AI가 넣은 코드 중 제거 0건, 사소한 3건은 유지 (가정)
- 상황: `/lean diff`(리허설)로 S0 커밋(1d04dda)의 코드 diff(`api/server.py` 106줄, `api/test_server.py` 55줄, `ui/index.html` 24줄) 덩어리 13개를 SPEC F2·CONTRACT B·C·D·S0 브리프와 대조
- 선택: 삭제·축소 0건. 흔한 후보(옵션·환경변수·캐시·재시도·락·로깅 설정·라우터 추상화·범용 에러 래퍼)는 브리프 "하지 말 것"이 사전에 막아 diff에 없다. 근거 없이 들어온 것은 사다리 1칸(기능·옵션·확장성·추상화)에 해당하지 않는 사소한 3건뿐이라 유지: ① argparse `description`·`help` 문자열(`--help`는 argparse 기본, 옵션 추가 아님) ② `ui/index.html`의 `body` 스타일 1줄(브리프 "필요 최소" 범위, S2가 비교 표 스타일과 함께 정리) ③ `finally: server_close()`(`with` 문과 같은 표준 종료 절차 2줄)
- 대안과 기각 이유: 사소한 3건도 지우기 — 동작 차이가 없고 S2에서 되돌리는 왕복만 생긴다 / `ThreadingHTTPServer`를 `HTTPServer`로 되돌리기 — D-009 기각 이유(브라우저 빈 연결) 그대로
- AI 제안 여부: AI(루트)가 "유지"를 추천 → 사람 확인 없이 수용(가정). 다시 볼 조건: S1·S3이 스텁(`# S0 stub`·`FIXTURES`)을 지울 때 `datetime`·`parse_qs`·`FIXTURES`가 미사용으로 남는지 `/lean diff`로 확인
