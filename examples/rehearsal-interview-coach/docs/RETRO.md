## 1. 무엇을 만들었나 (3문장)
프로 야구단 홍보팀 코치가 인터뷰 연습마다 선수별 체크리스트(항목 3개 × 상·중·하)와 한 줄 메모를 훈련장 노트북에 남기고, 선수 이름을 고르면 지난 세 번 연습과 비교하면서 그 자리에서 오늘 것을 적는 **비교 화면**을 목표로 한 로컬 도구다.
지금 저장소에 있는 것은 S0 "걸어다니는 뼈대"다: Python 표준 라이브러리 서버(`api/server.py`)가 기록 파일 1개를 읽어 선수 목록을 **계산해** 주고, HTML 한 장(`ui/index.html`)이 그 목록을 선수 선택 상자에 채우며, 비교·저장 API는 픽스처 스텁으로 응답한다(D-007).
비교 화면(S1·S2)과 입력·저장(S3·S4)은 아직 만들지 않았다 — 실제 마감이었다면 **제출 불가** 상태이며, 이 문서는 그 상태를 전제로 한 리허설 복기다.

## 2. 사용자와 핵심 흐름 (GLOSSARY 용어로)
- 사용자: 홍보팀 **코치** 2명. 훈련장 노트북 한 대를 같이 쓰므로 한 번에 조작하는 사람은 1명. **선수**는 도구를 조작하지 않고, 도구는 평가하지 않는다(**피드백**은 코치가 구두로).
- 흐름(to-be): 선수 이름 선택 → **지난 세 번** **연습**의 **체크리스트** **항목** 3개(핵심 메시지 전달·부정적 표현 회피·답변 길이)별 **상·중·하**가 한 화면에 → 그 자리에서 **오늘 것** 입력(+**메모** 한 줄, P1) → 저장. **기록** = 선수 × 연습 날짜 1건, 같은 날짜 재저장은 덮어쓰기.
- 지금 되는 흐름: 서버 기동 → 첫 화면의 선수 목록(가나다순)이 기록 파일에서 계산되어 보인다. 선수를 골라도 아직 아무 일도 일어나지 않는다(S2).

## 9. 예상 질문 10개와 한 줄 답
1. **Q: 지금 실제로 되는 게 뭔가?** A: 서버 한 줄 실행 → 기록 파일에서 계산한 선수 목록이 화면에 뜬다. 비교·저장은 스텁이라 미완이고, 남은 4 슬라이스와 검증 명령은 `docs/TASKS.md`에 있다.
2. **Q: 왜 DB 대신 JSON 파일 하나인가?** A: 동시 사용자 1명·시즌 500건 이하. 임시 파일→`os.replace`로 원자적이고, 파일 자체가 사람이 읽는 백업이다(D-001).
3. **Q: 왜 프레임워크 없이 표준 라이브러리 + HTML 한 장인가?** A: 설치 0·실행 한 줄, 선수 실명이 노트북 밖으로 안 나가고, curl·unittest로 검증된다. 화면 1장·엔드포인트 3개에 번들러는 과하다(D-002).
4. **Q: 도구가 평가까지 해 주면 더 좋지 않나?** A: 담당자가 "도구가 알아서 평가하는 건 원하지 않는다, 선수가 믿지 않는다"고 했다. 코치가 매기고 도구는 기록·비교만 한다(비목표).
5. **Q: api와 ui는 어떻게 병렬로 만드나?** A: 접점은 CONTRACT와 `fixtures/`뿐. S0 뼈대 서버가 픽스처 스텁을 돌려줘 ui의 Mock이 되고, S1·S3이 스텁을 바꾸면 같은 실행 명령이 실제 응답이 된다(D-007).
6. **Q: 같은 선수·날짜를 다시 저장하면?** A: 덮어쓰고 `replaced:true`. 화면은 기존 값을 입력란에 먼저 채워 '모르고 덮어쓰기'를 막는다. 409 확인창·이력 보존은 분기만 늘려 기각(D-004).
7. **Q: 기록 파일이 깨지면?** A: 서버가 시작을 거부하고 stderr 한 줄 + exit 1. 절대 빈 파일로 덮어쓰지 않는다 — JSON 아님·version 2·UTF-8 아님 3종으로 확인했다.
8. **Q: 어떻게 검증했나?** A: unittest 4개(픽스처→응답 계산 일치·임시 포트 왕복·손상 파일 거부·없는 파일=빈 상태) + SMOKE curl + Playwright 첫 화면·빈 상태. 슬라이스마다, 그리고 매시간 통합 체크포인트(TASKS.md).
9. **Q: AI가 넣으려던 것 중 뺀 것은?** A: 이력 보존·선수 id·미리 넣는 필드·Playwright 스크립트·락을 거절·축소했고, 옵션·라우터·캐시·로깅은 브리프 "하지 말 것"으로 사전 차단해 diff에 0건(D-004~D-010).
10. **Q: 토큰·시간을 어떻게 아꼈나?** A: 맥락을 전부 `docs/`에 두고 슬라이스마다 `/clear` 가능하게 했다. 서브에이전트에는 브리프 한 장(계약 샘플 값 + 하지 말 것)만 주고, ui는 api 코드를 열지 않는다. 세션 시작엔 TASKS와 SPEC P0만 읽고, `/lean`은 diff만 읽는다.
