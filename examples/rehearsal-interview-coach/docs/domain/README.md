# domain/ — 현업 지식 인덱스

> `/interview digest`가 갱신한다. 이 인덱스만 읽어도 "무엇을 아는지"가 보이도록 한 줄 요약을 유지한다.
> 모듈 세션은 자기 작업에 필요한 파일 하나만 연다. 주제가 늘면 파일을 추가한다.

| 파일 | 한 줄 요약 | 최종 갱신(인터뷰 회차) |
|---|---|---|
| persona.md | 프로 야구단 홍보팀 코치 2명이 훈련장 노트북 한 대를 같이 써 주 1회 사용. 가장 아픈 것은 선수별로 지난번과 비교 불가. 선수는 도구가 매긴 평가를 안 믿는다 | 2 |
| workflow.md | 코치가 홍보팀 엑셀 질문 목록(~30개)에서 그날 5개 선택 → 선수 3~4명 답변 → 코치가 항목 3개 상·중·하를 직접 매김 → 끝나고 구두 피드백(한 줄 메모면 충분) → 종이만 쌓임. to-be: 입력 → 저장 → 선수별 비교 | 2 |
| constraints.md | 텍스트 입력, 회당 15~20건·시즌 500건 이하, 노트북 1대·동시 사용자 1명 → 로컬 파일. 외부 AI 전송 금지(명시). 평가 단위·답변 텍스트 필수 여부·질문 목록 반입 방식 미확인 | 2 |
| success.md | "됐다" = 선수 이름 선택 → 지난 3회 연습의 항목별 상·중·하 한 화면 → 그 자리에서 오늘 것 입력. 하나만 된다면 비교 화면. 자동 평가는 원하지 않음 | 2 |

## 아직 모르는 것
- ③ 평가 단위: 상·중·하를 질문마다 적나 연습마다 한 번 적나. 2회차 표현("연습의 항목별 상·중·하")은 연습마다 한 번을 시사 → `/spec`은 그렇게 가정하고 간다.
- ③ 답변 텍스트를 도구에 받아 적어야 하나. "됐다" 장면에는 상·중·하와 메모만 있다.
- ③ 엑셀 질문 목록을 도구에 어떻게 넣나(붙여 넣기·파일) / 어떤 질문이었는지 기록에 남겨야 하나.
- ③ 코치 2명 중 누가 매겼는지 남겨야 하나 / 쌓인 종이를 옮겨 넣어야 하나.
- ④ 선수가 결과 화면을 같이 보나 (중요도 낮음).
- ⑤ 가설(입력 → 저장 → 선수별 비교, 녹음·로그인 제외)은 2회차에서 확인됨. 인터뷰는 여기서 멈추고 `/spec`으로.
- 질문 목록 전체는 `SPEC.md` 7절.
