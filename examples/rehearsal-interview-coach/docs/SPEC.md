## 1. 한 줄 목표
프로 야구단 홍보팀 **코치**가 인터뷰 **연습**마다 **선수**별 **체크리스트**(항목 3개 × 상·중·하)와 한 줄 **메모**를 종이 대신 훈련장 노트북에 남기고, **선수 이름을 고르면 지난 세 번 연습과 비교하면서 그 자리에서 오늘 것을 적는 비교 화면**을 쓰게 한다. 성공하면 종이 체크리스트 없이 연습 1회를 끝내고, 다음 주에 선수를 고르면 지난 기록이 바로 보인다. (인터뷰 1·2회차)

> 지시문(README.md)의 "선수가 답변하면 피드백을 줄 수 있는 도구"는 **코치가** 피드백을 주는 데 쓰는 기록·비교 도구로 읽는다. 도구는 평가하지 않는다 — 선수가 도구의 평가를 믿지 않는다. (인터뷰 2회차 확인)

## 2. 사용자와 상황
- 주 사용자: 프로 야구단 홍보팀 코치 2명. 훈련장 노트북 한 대를 같이 쓰므로 한 번에 조작하는 사람은 1명. 선수는 도구를 조작하지 않는다. (인터뷰 1·2회차; 마지막 문장은 가정)
- 사용 상황: 시즌 중 주 1회, 훈련장 노트북, 인터넷 됨. 연습 1회 = 선수 3~4명 × 세트(질문 5개 정도). 코치가 항목 3개를 상·중·하로 직접 매기고 끝나면 구두로 알려준다. (인터뷰 확인)
- 흐름(to-be, 담당자 확인): 선수 이름 선택 → 지난 세 번 연습의 항목별 상·중·하가 한 화면에 → 그 자리에서 오늘 것 입력 → 저장. 녹음·로그인 없음. (인터뷰 2회차)

## 3. 기능 우선순위
P0 = 없으면 제출 불가(3개 이하). P1 = 시간이 남으면. P2 = 이번엔 안 함. 근거 없는 기능은 P2 또는 비목표.

| ID | 우선순위 | 기능 | 완료 기준(검증 가능하게) | 근거(domain 파일·인터뷰 회차) |
|---|---|---|---|---|
| F2 | **P0** | 비교 화면: 선수 이름을 고르면 지난 세 번 연습의 항목별 상·중·하가 한 화면에 보인다. 3회 미만인 선수는 있는 만큼, 기록이 없으면 빈 상태 | `fixtures/records.sample.json` 사본으로 서버를 띄우고 브라우저에서 "김민수"를 고르면 10-16·10-09·10-02 세 연습의 항목 3개 상·중·하가 한 화면에 보이고 09-25는 보이지 않는다. ## 4. 비목표 (만들지 않을 것 — AI가 끼워 넣을 때 가리킬 근거)
- **자동 평가·AI 피드백·점수 제안**: 코치가 직접 매긴다. 도구가 매긴 것은 선수가 믿지 않는다. (인터뷰 2회차)
- **외부 AI·외부 API 호출 일체**: 선수 이름이 들어간다. 인터넷이 되어도 처리·저장은 노트북 안에서 끝낸다. (인터뷰 2회차)
- **녹음·음성인식·답변 텍스트 분석**: 녹음은 거의 듣지 않는다. (인터뷰 1회차)
- **로그인·권한·사용자 구분**: 코치 2명이 노트북 한 대. (인터뷰 1·2회차)
- **동시 쓰기·다중 기기 동기화·서버 배포·클라우드**: 동시 사용자 1명, 로컬 실행. (인터뷰 2회차)
- **DB(SQLite 포함)·ORM·마이그레이션**: 시즌 500건 이하, JSON 파일 1개. (D-001)
- **프론트 프레임워크·번들러·새 패키지**: Python 표준 라이브러리 + HTML/JS 한 장. (D-002, 가정)
- **질문 목록 반입(엑셀 파서)·세트 관리**: F5는 P2. (가정)
- **선수 명단 관리 화면**: 선수는 기록에 처음 적힐 때 생긴다. (D-005, 가정)
- **기록 삭제·수정 이력·되돌리기**: 수정은 같은 선수·날짜 덮어쓰기. 삭제는 파일 직접 수정. (D-004, 가정)
- **점수화·추세 그래프·통계·내보내기**: 상·중·하를 숫자로 바꾸지 않는다(미확정 사항을 선점하지 않음). 파일 자체가 내보내기다. (가정)
- **캐시·재시도·다국어·모바일 대응·배포 자동화**: 템플릿 기본 + 노트북 한 대. (가정)

## 5. 제약
- 데이터: 평가 = 항목 3개(핵심 메시지 전달·부정적 표현 회피·답변 길이) × 상·중·하, 코치가 직접 (인터뷰 확인). **평가 단위 = 연습마다 선수당 한 번** (가정 — 2회차 "연습의 항목별 상·중·하"). 세 항목을 모두 매겨야 저장된다 (가정). 메모 = 한 줄, 200자 이하 (한 줄은 인터뷰 확인, 200자는 가정). 규모 = 연습 1회당 기록 3~4건, 시즌당 100건 안팎(답변 기준 500건 이하) (수치 1회차, 합산 가정). 기록은 사람이 읽을 수 있는 JSON 파일 1개 `data/records.json` (D-001). 선수 식별 = 이름 문자열 그대로 (D-005, 가정).
- 실행 환경: 훈련장 노트북 한 대, 인터넷 됨, OS·브라우저 미확인 (인터뷰 확인). **Python 3.10 이상 + 최신 Chrome/Edge** (가정). `python3 api/server.py` 한 줄로 실행, 포트 8765 고정, 외부 패키지 설치 없음 (D-002, 가정). 선수 이름이 들어가는 데이터는 노트북 밖으로 나가지 않는다 — `data/`는 커밋하지 않는다 (인터뷰 확인).
- 읽기/쓰기: 동시 사용자 1명, 쓰기 충돌 없음 (인터뷰 확인). 저장은 파일 전체를 임시 파일에 쓰고 교체한다 — 중간에 꺼져도 기존 기록은 남는다. 파일이 깨져 있으면 서버는 시작하지 않고 알린다, 덮어쓰지 않는다.
- 예외·엣지: 선수 3~4명·질문 5개 정도로 가변 — 개수를 고정하지 않는다 (인터뷰 확인). 3회 미만인 선수는 있는 만큼, 첫 참여는 빈 상태 (가정). 같은 선수·같은 날짜 재저장 = 덮어쓰기, 화면은 기존 값을 먼저 보여준다 (D-004, 가정). 날짜는 바꿀 수 있다(지난 연습을 뒤늦게 입력) (가정). 이름 오타·동명이인은 다른 선수로 취급된다 — 화면은 기존 이름 목록에서 고르게 해 오타를 줄인다 (D-005 shortcut).

## 6. 성공 지표
- 담당자의 "됐다" 장면: 선수 이름을 고르면 지난 세 번 연습의 항목별 상·중·하가 한 화면에 보이고, 그 자리에서 오늘 것을 바로 적을 수 있다. 이 장면이 `fixtures/records.sample.json`으로 재현되면 완료. (인터뷰 2회차)
- 보조 지표 (가정, 담당자가 수치를 말하지 않음): 연습 1회를 종이 체크리스트 0장으로 끝낸다 / 선수를 고른 뒤 추가 클릭 없이 지난 3회가 보인다.
